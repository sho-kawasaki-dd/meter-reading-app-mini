## 1. 目的・範囲

確定済みの検針結果を用途・場所・測定定義ごとに集計し、複数の測定定義を組み合わせた使用量も確認できるようにする。集計結果はダッシュボードと CSV / PNG で確認する。併せて、安全な手動バックアップ・復元と Windows 向け配布基盤を整備する。

集計式の例: オーナー使用量 = 引込電力量計 − (ホテル電灯電力量計 + ホテル動力電力量計)

| 区分 | 本書の対象 |
| --- | --- |
| Phase 5a | 集計式マスタ、スキーマ v4、集計 Service、ダッシュボード、CSV / PNG |
| Phase 5b | バックアップ・復元 UI、復元候補の検査・移行、現行 DB の保全・置換・再起動 |
| Phase 5c | Windows x64 配布、ライセンス・対応ソース、Release 下書きの自動作成 |

5a・5b・5c はマイルストーンとして記録するが、作業用計画書は本書だけとする。5a 完了時には本書を凍結・移動せず、Phase 5 全体の完了時に一度だけ凍結する。計画に記載した機能・成果物は、実装・検証するまで完成済みと扱わない。

各マイルストーンの完了条件は、該当する PR のチェック、9 章の該当項目、Windows / Ubuntu の必須 CI 成功とする。5c の Release 下書きの実績確認 (5c-4) は利用者のタグ承認に依存するため、承認待ちの間も 5a・5b の完了は個別に記録できる。Phase 5 全体の完了と凍結は、5c-4 の完了後に一度だけ行う。

## 4. Phase 5a: 集計式とスキーマ

### 4.1 スキーマ v4

- `aggregation_formulas`: `formula_id`、`display_name`、`unit`、`category`、`cycle_group`、`purpose`、式の表示小数桁数を保持する。名称・表示桁数の変更は過去の数値を変更しない。
- `aggregation_formula_versions`: `formula_id`、`effective_from_date`、有効 / 無効、UTC の登録日時、登録時の業務日を保持する。主キーは (`formula_id`, `effective_from_date`) とする。
- `aggregation_formula_terms`: 版のキー、`measurement_definition_id`、`coefficient`、`sort_order` を保持する。係数は有限の plain decimal 文字列で 0 を禁止し、版内の測定定義と表示順の重複を禁止する。
- 有効版は 1 項目以上を必須とし、無効版は項目を持たない。無効化・再有効化を日付で解決するため、元の 5a 案にあったヘッダーの `is_active` を現在状態の別正本として重複保持しない。指定日の状態は適用版から求める。
- 対象日に版がない、または無効版が適用される式は、その日には適用しない。期間の一部だけ適用される場合は適用対象期間を表示し、全期間の完全な値と誤認させない。
- 初版だけ過去日を選択できる。登録時業務日と適用開始日から後付け適用を明示する。版が 1 つだけの間は、初版の開始日・項目・係数を過去日を含めて再保存できる (D25)。2 版以上になった後は、現在業務日 (D27) 以降に限り版を追加・変更し、同一開始日の再保存は項目全体を原子的に更新する。
- 初版の誤りが 2 版目の追加後に判明した場合は、新しい式を作成して旧式を無効化する。物理削除や過去版の書換えはしない。
- 現在業務日の再保存は同日の既存結果にも影響すること、将来版がある場合はその後の状態が変わり得ることを保存前に表示する。将来版を無断で削除・変更しない。新しい版の開始日は既存の将来版の開始日と重複させず、同一開始日は再保存として扱う。将来版の間への挿入は、前後の版の状態を表示したうえで許可する。
- 式・測定定義の物理削除は行わない。無効化済み定義の過去の項目参照は残し、過去集計に注記する。新規版で無効化済み定義を新たに使用しない。
- [schema.sql](../../src/meter_reading_mini/db/schema.sql)、v3→v4 移行、`SCHEMA_VERSION`、版別スキーマ検査を同時に更新する。現行 v3 の DDL を `schema_v3.sql` として固定し、v2 はその v3 DDL から生成する。v1 は既存の版別 DDL を維持する。各版の移行・検査・`PRAGMA user_version` 更新を同一トランザクションで行う。
- SQLite の制約に加え、Service と復元時の業務整合性検査で、日付・状態・項目数・係数・参照先・計算方法・値形式・単位・カテゴリ・周期グループを検証する。負の係数は有効であり、既存の非負数用 Decimal 検査をそのまま適用しない。

### 4.2 層構成・操作境界

- 集計式・版・項目・集計結果・フラグの契約と、`db/integrity.py`・Service の双方で共有する周期グループ解決・係数検証等の純関数は、既存の契約または `CONTRACT_MODULES` / `DATABASE_CORE_IMPORTS` に登録した独立した契約モジュールに定義し、`db/` から Service への逆依存を作らない。独立モジュールを追加する場合は層の依存テスト (`tests/test_contract_boundaries.py`) を更新する。
- 集計式の CRUD と集計用の予定枠・結果・交換境界の読取を Repository Protocol と sqlite3 実装に追加する。SQL 値はプレースホルダで渡す。
- `core/aggregation_formulas.py` は式の登録・版管理、`core/reports.py` は集計を担当する。Service がトランザクション境界を持ち、UI から SQL・Repository を直接扱わない。`AggregationFormulaService` は `current_business_date_provider` と `clock` を受け取り、`create_app_context` から共通の注入時計・現在業務日を渡す。
- 式の保存と、過去版・無効版を含め `aggregation_formula_terms` から参照されている測定定義に対する `unit`・`category` 変更の拒否 (`MeasurementDefinitionService.update_measurement_definition`) は、それぞれ Service の同一トランザクション内で検証する。式に参照されていない測定定義の `unit`・`category`・`purpose` を変更する場合は、過去の直接集計の表示・分類も変わることを保存前に警告・確認する (D15)。DB 制約違反は適切な `DomainError` 派生例外へ変換する。
- 項目条件は式の保存時だけでなく集計時にも検証し、不整合を欠測・0 にせず理由を通知する。測定定義の周期・値形式・計算方法を作成後に変更できない既存ルールを維持する。無効化済み定義の過去参照は許可して注記する。
- 集計に必要な予定枠・結果・前回基準・交換境界・式版を一貫した読取スナップショットで取得する。前回実測の順序は既存と同じ `scheduled_at, planned_reading_id` とする。

## 5. Phase 5a: 集計・フラグ・表示

### 5.1 使用量と期間

- `task_state = 'completed'` かつ `result_status = 'measured'` の `reading_transactions.usage_delta` と、`replacement_boundaries.old_meter_usage_delta` を使用する。`superseded` の予定枠は対象外とし、交換境界は予定枠との結合による欠落・重複なく一度だけ加える。
- 集計対象の測定定義は `delta` / `decimal_string` とする。`raw_only`・力率は使用量として 0 にせず、対象外である理由を表示する。
- 実測済みの `delta` に使用量がない等、状態と値が不整合なデータは 0 や通常の欠測に変換せず、業務エラーとして通知する。
- 確認待ちの割当に属する結果・交換境界は集計に使用せず、対象と理由、計算条件の訂正画面への導線を示す。他に計算可能な値があれば部分値を参考値として表示する。
- 定義ごと・業務日ごとの使用量に、その日に有効な式版の係数を掛け、日・月・年へ合計する。1 期間に複数版があれば版ごとの寄与を合算し、適用版を明細に残す。
- データ検索は保存済み `business_date` の `[開始日, 終了日)` とする。翌日 00:00 の予定枠は `day_offset = 1` で割り当てられた前日分に入る。交換境界も保存済みの業務日に入れる。
- 年次の暦年は 1 月 1 日以上・翌年 1 月 1 日未満、年度は 4 月 1 日以上・翌年 4 月 1 日未満とする。進行中の月・年は現在業務日までの途中値と示し、未来日を 0 や欠測として捏造しない。
- 月次・隔月の項目ごとに「前回基準の業務日 < 検針対象期間 <= 今回の業務日」を示す。交換や複数実測を含む場合は基準の出所と各区間を保持し、項目間の期間不一致を判定する。
- 係数・元使用量・寄与・合計は Decimal で計算し、加算・乗算の途中を丸めない。既存の `decimal_arithmetic.py` を再利用し、大きな桁数でもグローバル精度に依存しない。

| 情報 | `INFO_VERSION_SWITCH` | 期間内に式版の切替がある |
| 情報 | `INFO_MULTI_LOCATION` | 複数場所を含む |

- 予定がない期間と予定があって未実測の期間を区別する。全項目に実測・有効な交換使用量がなければ数値なしとし、実際に計算された 0 と混同しない。複数項目の式では、(1) 全項目に実測または有効な交換使用量があれば通常計算値 (他の欠測系条件がない場合)、(2) 一部の項目にのみ実測・有効な交換使用量があれば部分計算値 (参考値) とし `MISSING_PARTIAL_ITEMS` と未実測項目の該当 `MISSING_*` を付与、(3) 全項目とも実測・有効な交換使用量がなく、いずれかの項目に未完了枠・非実測枠・確認待ち割当等があれば数値なしとし該当 `MISSING_*` を付与、(4) 全項目とも期間内に予定枠・交換自体が存在しなければ数値なし・欠測フラグなしとする。
- 交換日の旧メーター分と新メーター分を合算する。必要な読値と基準がそろった交換そのものは欠測扱いにしない。不足があれば交換情報を残したまま参考値にする。
- 新初期値がない場合の新メーター初回使用量 0 は既存仕様どおり維持し、基準不明を集計上で明示する。後日の交換履歴訂正や過去の検針訂正後は、保存済み値・境界の再計算結果を使って集計し直す。
- 日別の部分結果のフラグを単純に月・年へ引き継ぐのではなく、選択した集計期間について必要な項目・予定・基準を評価する。例えば月次項目 A が 20 日、B が 30 日に実測される場合、20 日の式は部分値・参考値とし、月全体では両項目を集計して他の欠測や期間またぎを別途判定する。
- `purpose` は定義の直接集計では現在の定義、式では式自身の値で判定する。式の項目には別目的の定義も使えるが、式と構成定義を無条件に合算しない。表示は D28 に従い、同一定義が直接集計と式の両方に現れても合計欄で重複して加算しない。

### 5.3 ダッシュボード・CSV / PNG

- `ui/widgets/dashboard.py` の `DashboardWindow` で測定定義と式を選択し、日次・月次・暦年・年度、`purpose`、カテゴリ、場所で絞り込み、推移グラフと内訳を表示する。異なる単位の系列を同じ軸に無条件で混在させない。
- 複数場所の式は、表示対象期間の有効版の項目のいずれかが選択場所に一致すれば候補に表示する。絞り込みで項目を削らず全項目で計算し、場所と寄与を明細に表示する。
- `MasterDialog` に式タブを追加し、項目条件・係数・版履歴・後付け初版・無効化の影響を保存前に表示する。参照中定義の属性変更は理由と対応方法を表示する。
- 入力・訂正・交換・式変更後はダッシュボードを再取得または無効化する。取得失敗時に古い表・グラフを正常な結果として残さず、古い結果を CSV / PNG 出力しない。
- 測定定義は現在の `decimal_places`、式は式ごとの表示桁数を使う。表示桁数が未指定なら無丸めとし、指定時は `ROUND_HALF_UP` で四捨五入する。過去に保存した値の精度を変更・再検証しない。
- Qt Charts の描画座標に必要な浮動小数点変換は UI 内の表示に限定し、業務計算・表・CSV の正本に使わない。描画可能範囲外は明示し、数値を 0 や有限値に置き換えない。
- CSV は UTF-8 BOM 付きとし、固定ヘッダーで少なくとも次の列を持つ。期間終了は含まない境界である。

  `行種別、集計単位、期間開始業務日、期間終了業務日_含まない、対象種別、対象ID、対象名、目的、カテゴリ、単位、場所ID、式版開始業務日、後付け設定、測定定義ID、係数、明細元、明細ID、基準業務日、実測業務日、元使用量_無丸め、表示値、無丸め値、欠測系、警告、情報`

- CSV の行種別は集計行と明細行を区別する。明細は式版・項目・検針区間 / 交換境界を追跡できる単位で出力し、複数版をまたぐ期間も再計算の根拠を確認できるようにする。集計行では明細固有列 (`測定定義ID`・`係数`・`明細元`・`明細ID`・`基準業務日`・`実測業務日`・`元使用量_無丸め`) を空欄とし、直接集計の集計行や複数版の期間をまたぐ式の集計行では単一に定まらない `式版開始業務日`・`後付け設定` も空欄とする。複数場所を含む式の集計行では関連する `場所ID` を昇順 `;` 区切りで出力し、明細行では各測定定義の `場所ID` と、元使用量に係数を掛けた項目の寄与値 (`無丸め値` および式の表示桁数による `表示値`) を出力する。値なしは空欄であり 0 ではない。
- `欠測系`・`警告`・`情報` 列には 5.2 のコードを `;` 区切りで出力し、なしは空欄とする。コードは英大文字で始まるため数式注入対策の対象外とする。
- 文字列セルの先頭が `=`・`+`・`-`・`@`・タブ・CR の場合は `'` を付ける。数値列には付けず、負の係数・結果も数値として出力する。CSV の無丸め値を表計算ソフトで取り込む際の精度上の注意を案内する。
- PNG は表示中のグラフを出力する。CSV・PNG は既存の出力ダイアログを再利用し、書込・クローズ・置換の完了を確認して成功を通知する。PNG 保存 API が失敗を返した場合もエラーとして扱う。
- 1366×768・文字サイズ 150% で操作に到達でき、グラフが描画できない値でも表・CSV の正確な値を利用できるようにする。

## 6. Phase 5b: バックアップ・復元

### 6.1 バックアップ

- 既存の `copy_database()` と `sqlite3.Connection.backup()` を使用し、WAL にあるコミット済みデータを含める。保存先を利用者が選択し、既存ファイルや現行 DB と同一のファイルを無断で上書きしない。
- 既定名は `meter_reading_YYYYMMDD_HHMMSS.db` とし、業務タイムゾーンの日時を用いる。ファイル作成・コピー・クローズが完了してから成功を通知し、失敗時は作成した途中ファイルだけを安全に片付ける。
- 保存先の権限不足、容量不足、同名ファイル、キャンセル、コピー失敗を通知または明示的に扱う。業務データをログへ出力しない。

### 6.2 復元手順

1. 復元元が現行 DB と同一でないことを実体も含め確認し、`mode=ro` で開く。`user_version`、版別スキーマ、`integrity_check`、`foreign_key_check` を検査し、未対応の旧版・新版や破損を拒否する。
2. 復元元を変更せず、現行 DB と同じファイルシステム上の専用一時 DB へ SQLite バックアップでコピーする。コピー側を再検査し、必要なら最新版へ移行する。
3. 一時 DB の業務整合性を検査する。Decimal・状態と値の対応・割当・訂正履歴・交換境界・式版・係数・参照条件を含める。確認待ち割当と同一場所の名称不一致は復元不可エラーと分けて警告する。移行・検査後はチェックポイントを完了して一時 DB 接続を閉じ、単一ファイルに統合された状態にする。
4. 検査済みの一時候補に対して復元内容・警告・現行 DB の上書き・再起動を利用者に確認する。キャンセル、入力変更、検査失敗時に旧候補を確定しない。
5. 確定時に候補を再検証し、操作・タイマーを停止する。現行 DB を `backups/pre-restore_日時.db` に SQLite バックアップで保全する。同名衝突や保全失敗時は置換しない。
6. 接続と WAL の状態を確認し、`app.py` の `ExitStack` による二重クローズを避けて現行 DB のチェックポイントと接続クローズを完了させる。`-wal` / `-shm` が残っていないことを確認し、多重起動ロックを保持したまま一時 DB を `os.replace()` で原子的に置換する。ビジーやチェックポイント・置換の失敗時は現行 DB を保持し、成功と表示しない。所有を確認できない `-wal` / `-shm` を無条件に削除しない。
7. 「イベントループ終了 → DB クローズ → DB 置換 → ロック解放 → 新プロセス起動」の順序で、実行形態に応じてアプリを再起動する。起動要求だけを成功とせず、再起動を確認できない場合は手動起動と保全バックアップの場所を案内する。`ui_settings.json` は復元しない。

- 置換前の例外・キャンセル・候補不正では現行 DB を変更しない。置換後の再起動失敗時も保全バックアップを保持し、復旧手順を明示する。
- 復元元の変更・同一ファイル・一時 DB の改変、コピー・移行・COMMIT・保全・チェックポイント・置換・再起動の失敗を、実ファイル DB と障害注入で検証する。
- UI は Service を呼び、DB 接続の終了・ロック保持・再起動の引き継ぎはアプリ起動オーケストレーションと協調する。Python 実行と PyInstaller 実行の双方で保存先指定を引き継ぐ。
