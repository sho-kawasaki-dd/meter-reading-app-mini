## 1. 目的・範囲

連成計 (正圧・負圧を 1 つの計器で示す圧力計) のように、読値が負になる計器を検針できるようにする。差分を計算せず読値だけを記録する `calculation_method = 'raw_only'` の測定定義に限り、符号付きの読値を受け付ける。

影響範囲を抑えるため、測定定義の属性や DB スキーマは追加しない。計算方法 `raw_only` を負数を許容する条件とし、既存の読値検証の各経路でこの条件を判定する。

| 対象 | 対象外 |
| --- | --- |
| `raw_only` かつ `decimal_string` の実測値 (PC 直接入力・訂正、スマホ取込) の負数許容 | `delta` の読値・前回値・使用量の負数 (従来どおり拒否) |
| `raw_only` の交換境界の旧最終読値・新初期読値の負数許容 | 倍率・警告閾値・ロールオーバー値・読値初期値・力率の符号の変更 |
| 検針シートの「±」切替ボタンと符号付き入力の検証 | 測定定義ごとの「負数を許可」設定 (スキーマ変更を伴うため不採用) |
| 負のゼロ (`-0`・`-0.00` 等) の全経路での拒否 | 読値の下限・範囲による警告 |
| 集計・検針履歴・復元時の整合性検査の対応 | DB スキーマ・移行の変更 (v5 を維持) |
| シート・下書き・結果の形式 v1 と MR1 パーサの互換性維持 | シート・下書き・結果の形式の版数変更 |
| `pyproject.toml`・`uv.lock` のアプリ版数を `0.2.3` に更新 | タグ付け・Release 作成・正式配布 |
| 改修後の Windows 検証用インストーラーのビルド・成果物検査 | 開発 PC でのインストール・既定保存先での起動 |
| 正本・README の更新 | v0.2.3 で保存した負の読値を含む DB の旧版アプリでの利用 (ダウングレード) |

検証用成果物は正式な配布物ではなく、Release に添付しない。インストールを伴う実地確認は、実データのない Sandbox / VM で利用者が行う。タグ付け・Release は別途、利用者の承認と Phase 5c の手順に従う。

## 2. 決定事項

利用者確認 (2026-11-26) で確定した方針は以下のとおり。

| # | 論点 | 決定 |
| --- | --- | --- |
| D1 | 負数を許容する範囲 | `raw_only` のすべての測定定義で許容する。測定定義ごとのフラグは設けず、スキーマを変更しない |
| D2 | 交換時の読値 | `raw_only` の旧最終読値・新初期読値も負数を許容する |
| D3 | スマホでの負号入力 | `raw_only` の数値入力欄に「±」切替ボタンを追加する。入力欄の `inputmode="decimal"` は維持する |
| D4 | 負のゼロ | `-0`・`-0.00` 等は入力エラーとし、正規化して保存しない |
| D5 | 版数・検証用ビルド | アプリ版数を `0.2.3` に更新し、v0.2.2 と同じ手順で検証用インストーラーをビルド・検査する |

### 2.1 その他の前提 (計画として採用)

- 負数を許容する条件は「測定定義が `calculation_method = 'raw_only'` かつ `value_schema = 'decimal_string'`」とし、判定を core の 1 か所 (例: `reading_values.py` の `allows_negative_reading`) にまとめる。各経路で条件を個別に記述しない。
- 符号付き読値の文字列は、既存の `SIGNED_DECIMAL_STRING_PATTERN` (`^-?\d+(\.\d+)?$`) に従う。`+` 記号・指数・カンマ・空白・`-.5` のような整数部の省略は従来どおり拒否する。
- 負のゼロは、符号付き・符号なしを問わず、すべての読値検証で拒否する。Python から渡された `Decimal("-0")` も拒否する。
- 小数桁数 (`decimal_places`) の検証は、符号を除いた小数部に従来どおり適用する。
- `raw_only` にロールオーバー値が設定されている場合、従来どおり「読値 < ロールオーバー値」の上限検査のみを行い、下限検査は設けない。
- `raw_only` は使用量を計算しない (`usage_delta = None`) ため、負の差分の拒否・ロールオーバー補正・閾値警告・集計には影響しない。集計では従来どおり「集計対象外」とする。
- `delta` で負の読値を入力した場合は、従来どおり入力エラーとする。PC の入力欄・スマホのシート・取込時の検証のいずれでも拒否する。
- MR1・結果 JSON の `raw_reading` は従来どおり plain decimal 文字列であり、符号付きの値を含められる。形式の版数は v1 のままとし、従来の (非負の) 結果も引き続き取り込める。
- v0.2.2 以前に出力した検針シートは「±」ボタンを持たず、負数の入力を拒否する。負数を入力する場合は v0.2.3 でシートを再出力する。旧シートの結果は v0.2.3 で取り込める。
- v0.2.3 で負の読値を保存した DB・バックアップを v0.2.2 以前のアプリで開いた場合や、旧版で復元した場合の動作は保証しない。ダウングレード非対応として README に記載する。
- CSV の「読値」「前回値」列は数値列として扱われており、先頭が `-` でも数式対策の `'` を付けない。この扱いは変更しない。

## 3. 設計

### 3.1 core の読値検証

- `reading_values.validate_reading_value` にキーワード引数 `allow_negative: bool = False` を追加する。既定値を `False` として、引数を省略した呼出しでは従来どおり負数を拒否する (安全側に倒す)。負のゼロは `allow_negative` にかかわらず拒否する。
  - エラー文言は条件に応じて分ける (例: 「読値は有限の 0 以上の数値で指定してください。」「読値に負のゼロは指定できません。0 を入力してください。」)。
- `validate_initial_reading` は `delta` 専用のため変更しない (負数は従来どおり拒否)。
- `assignment_calculation.validate_assignment_reading` は、受け取る測定定義から負数の許容を判定する。`ReadingPrecision` Protocol に `calculation_method`・`value_schema` を追加するか、許容の可否を引数で受け取る。`validate_persisted_assignment_reading` にも同じ判定を渡す引数を追加する。
- 呼出し元 (`manual_reading_validation.py`、`reading_write_orchestration.py`、`reading_preview.py`、`assignment_calculation.py` の交換境界の計算、`assignment_calculation_settings.py`、`meter_replacement_service.py`) で、測定定義の計算方法に基づいて判定を渡す。
- `UsageDeltaCalculationService` は `raw_only` で差分を計算しないため変更しない。

### 3.2 契約 (`contract_models.py`)

- 符号付き・有限・負のゼロ拒否の読値型 (仮称 `SignedReadingAsString`) を追加する。既存の `SignedDecimalAsString` (集計式の係数等で使用) の意味は変更しない。
- `MeterReadingSubmission.raw_reading` は、転送時の形式検証として符号付きを受け付ける。計算方法は予定枠の解決後に判明するため、転送時に符号を判定しない。
- `ResolvedMeterReadingSubmission` に `calculation_method` を追加する。`raw_only` 以外の負の読値は解決時に拒否する。`resolve_meter_reading_submission` と `meter_reading_sync.ReadingSubmissionResolver` の型に計算方法の引数を追加する。
- 交換の読値 (`ReplacementDefinitionReadingSubmission`、`MeterReplacementSubmission` の読値) も符号付きを受け付け、測定定義の解決後に `meter_replacement_service.py` で計算方法に基づいて検証する。
- JSON スキーマ (`WithJsonSchema`) は符号付きのパターンを示す。
- 契約の独立性 (Service・UI・DB 実装に依存しないこと) を維持する。

### 3.3 集計・検針履歴

- `reports.py` の実測結果・交換境界の検証 (`_validate_reading` 相当、`_DefinitionHistory` の欠測判定、`_observe_boundary`) で、`raw_only` の読値列だけを負数判定から除外する。`delta` の読値・前回値・使用量・交換境界の負数は、従来どおり不整合として業務エラーにする。
- `reading_history.py` の状態不整合判定 (`HIST_STATE_MISMATCH`) も同様に、`raw_only` の読値・交換読値の負数を不整合にしない。
- 使用量集計・集計式・JSON 一括出力の値とコードは変更しない (`raw_only` は集計対象外のまま)。負のゼロが保存されている場合は不整合とする。

### 3.4 DB 整合性検査 (復元時)

- スキーマ・`SCHEMA_VERSION`・移行処理は変更しない (DB の読値列に符号の CHECK 制約はない)。
- `db/integrity.py` の `_DECIMAL_FIELDS` による一律の「0 以上」検査から、`raw_only` で負になり得る列 (`reading_transactions.raw_reading`、`replacement_boundaries` の `previous_measured_reading`・`old_final_reading`・`new_initial_reading`、`replacement_events` の旧読値列) の符号検査を外す。これらの列の符号は、測定定義の計算方法を参照する既存の結果・交換境界の検査で判定する。
  - `raw_only` の読値は負数を許容し、`delta` の読値・前回値・使用量は従来どおり 0 以上を要求する。
  - 負のゼロは計算方法にかかわらず拒否する。
- その他の Decimal 列 (倍率・閾値・ロールオーバー値・読値初期値・使用量等) の検査は変更しない。

### 3.5 PC 画面

- `DecimalLineEdit` に `allow_negative: bool = False` を追加する。`True` の場合は符号付きのパターンを受け付け、負のゼロを拒否し、プレースホルダーを「例: -12.5」等にする。既定の動作は変更しない。
- `direct_reading_dialog.py` の測定値と `replacement_definition_editor.py` の旧最終読値・新初期読値で、対象の測定定義が `raw_only` の場合だけ `allow_negative=True` にする。測定定義を切り替える画面では、切替時に設定を更新する。
- 最終的な検証は core で行い、UI の検証は入力形式の早期通知にとどめる。
- 読値の表示・CSV 出力は既存の Decimal 表示を使い、負数の表示を確認する。

### 3.6 検針シート (`mobile_reading_assets/sheet.js`)

- 既存の `DECIMAL_PATTERN` と `parseDecimal` (倍率・ロールオーバー値・力率等で使用) は変更しない。`raw_only` の測定値の検証にだけ符号付きの解析を使う。BigInt による固定小数点の表現・比較・書式化が負数を扱えることを確認する。
- `raw_only` の数値入力欄の隣に「±」切替ボタンを表示する。`delta` と力率の入力欄には表示しない。
  - 押下時は入力値の先頭の `-` を付け外しする。空欄では `-` を入力した状態にし、入力欄へフォーカスを戻す。
  - 切替は通常の入力変更と同じ処理を通す (確認の解除、IndexedDB への自動保存、同日後続枠の前回値の再表示)。
  - `aria-label` (例: 「符号を切り替え」) を付け、スマホ縦横・PC で操作できる大きさ・配置にする。
- `raw_only` の入力エラーの文言を、負数を入力できることが分かる内容にする (例: 「数値を、指数・カンマなしで入力してください。負数は先頭に - を付けます。」)。負のゼロ・`-` だけの入力は入力エラーとし、確認済みにしない。下書きには入力途中の状態として保持する。
- `delta` に `-` が入力された場合は従来どおり入力エラーとする。
- 前回値として表示する `initial_last_reading` やシート内の先行枠の読値が負数でも、正しく表示されることを確認する (`raw_only` は参考使用量を計算しない)。
- シート・下書き・結果のデータ形式は v1 のままとし、キーを追加しない。

### 3.7 版数・検証用インストーラー

- `pyproject.toml` の版数を `0.2.3` に更新し、`uv lock` で `uv.lock` を更新する。アプリ版数を参照するテスト・表示・配布設定・文書を確認し、必要な箇所を更新する。`SCHEMA_VERSION` とスキーマ v5 は変更しない。
- 本計画書を `packaging/source-files.txt` に登録し、凍結・移動時にパスを更新する。`src/`・`tests/` に新規ファイルを追加する PR では、同じ PR で同ファイルも更新する。
- 機能・版数の PR がマージされた `main` の対象コミットから、`scripts\build_distribution.py --verification-only` で検証用インストーラーを新規ビルドする。開発 PC ではインストーラーを実行せず、一時保存先で exe を直接起動して確認する。
- Sandbox / VM での実地確認 (利用者実施) では、v0.2.2 からの更新とデータ保持、`raw_only` の負の読値の入力・表示・バックアップ / 復元を確認対象に加える。
