## 1. 目的・範囲

連成計 (正圧・負圧を 1 つの計器で示す圧力計) のように、読値が負になる計器を検針できるようにする。差分を計算せず読値だけを記録する `calculation_method = 'raw_only'` の測定定義に限り、符号付きの読値を受け付ける。

影響範囲を抑えるため、測定定義の属性や DB スキーマは追加しない。計算方法 `raw_only` を負数を許容する条件とし、既存の読値検証の各経路でこの条件を判定する。

| 対象 | 対象外 |
| --- | --- |
| `raw_only` かつ `decimal_string` の実測値 (PC 直接入力・訂正、スマホ取込) の負数許容 | `delta` の読値・前回値・使用量の負数 (従来どおり拒否) |
| `raw_only` の交換境界の旧最終読値・新初期読値の負数許容 | 倍率・警告閾値・ロールオーバー値・読値初期値・力率の負数許容 (負のゼロの扱いは下記) |
| 検針シートの「±」切替ボタンと符号付き入力の検証 | 測定定義ごとの「負数を許可」設定 (スキーマ変更を伴うため不採用) |
| 新規の実測値・交換読値・読値初期値・警告閾値での負のゼロ (`-0`・`-0.00` 等) の拒否、および保存済みの読値初期値・警告閾値に限った互換対応 | 読値の下限・範囲による警告 |
| 集計・検針履歴・復元時の整合性検査の対応 | DB スキーマ・移行の変更 (v5 を維持) |
| シート・下書き・結果の形式 v1 と MR1 パーサの互換性維持 | シート・下書き・結果の形式の版数変更 |
| `pyproject.toml`・`uv.lock` のアプリ版数を `0.2.3` に更新 | タグ付け・Release 作成・正式配布 |
| 改修後の Windows 検証用インストーラーのビルド・成果物検査 | 開発 PC でのインストール・既定保存先での起動 |
| 正本・README の更新 | v0.2.3 で保存した負の読値を含む DB の旧版アプリでの利用 (ダウングレード) |

検証用成果物は正式な配布物ではなく、Release に添付しない。インストールを伴う実地確認は、実データのない Sandbox / VM で利用者が行う。タグ付け・Release は別途、利用者の承認と Phase 5c の手順に従う。

## 2. 決定事項

利用者確認 (2026-11-26) で確定した方針は以下のとおり。

| # | 論点 | 決定 |
| --- | --- | --- |
| D1 | 負数を許容する範囲 | `raw_only` のすべての測定定義で許容する。測定定義ごとのフラグは設けず、スキーマを変更しない |
| D2 | 交換時の読値 | `raw_only` の旧最終読値・新初期読値も負数を許容する |
| D3 | スマホでの負号入力 | `raw_only` の数値入力欄に「±」切替ボタンを追加する。入力欄の `inputmode="decimal"` は維持する |
| D4 | 負のゼロ | 新規入力の `-0`・`-0.00` 等は入力エラーとし、正規化して保存しない。保存済みの値の互換対応は 2.1・3.4 に定める |
| D5 | 版数・検証用ビルド | アプリ版数を `0.2.3` に更新し、v0.2.2 と同じ手順で検証用インストーラーをビルド・検査する |

### 2.1 その他の前提 (計画として採用)

- 負数を許容する条件は「測定定義が `calculation_method = 'raw_only'` かつ `value_schema = 'decimal_string'`」とし、判定を契約層の 1 か所 (`contract_models.py` の `allows_negative_reading`) にまとめる。各経路で条件を個別に記述せず、契約モジュール間の依存を一方向に保つ。
- 符号付き読値の文字列は、既存の `SIGNED_DECIMAL_STRING_PATTERN` (`^-?\d+(\.\d+)?$`) に従う。PC・スマホの画面入力では前後の空白を従来どおり除去してから検証し、MR1・結果 JSON の `raw_reading` 自体には前後を含め空白を許さない。`+` 記号・指数・カンマ・数値内部の空白・`-.5` のような整数部の省略は拒否する。
- 新規の実測値・交換読値・読値初期値・警告閾値では、入力・訂正経路を問わず負のゼロを拒否する。Python から渡された `Decimal("-0")` も拒否する。
- v0.2.2 では `Decimal("-0.00")` を警告閾値・読値初期値として保存でき、業務整合性検査も通る。既存 DB・バックアップを引き続き使えるよう、この 2 項目に保存済みの負のゼロに限り、読み出し・復元時の検査で符号なしのゼロとして扱う。保存済みの文字列は書き換えない (3.4 参照)。
- 小数桁数 (`decimal_places`) の検証は、符号を除いた小数部に従来どおり適用する。
- `raw_only` にロールオーバー値が設定されている場合、従来どおり「読値 < ロールオーバー値」の上限検査のみを行い、下限検査は設けない。
- `raw_only` は使用量を計算しない (`usage_delta = None`) ため、負の差分の拒否・ロールオーバー補正・閾値警告・集計には影響しない。集計では従来どおり「集計対象外」とする。
- `delta` で負の読値を入力した場合は、従来どおり入力エラーとする。PC の入力欄・スマホのシート・取込時の検証のいずれでも拒否する。
- MR1・結果 JSON の `raw_reading` は従来どおり plain decimal 文字列であり、符号付きの値を含められる。形式の版数は v1 のままとし、従来の (非負の) 結果も引き続き取り込める。
- v0.2.2 以前に出力した検針シートは「±」ボタンを持たず、負数の入力を拒否する。負数を入力する場合は v0.2.3 でシートを再出力する。旧シートの結果は v0.2.3 で取り込める。
- v0.2.3 で負の読値を保存した DB・バックアップを v0.2.2 以前のアプリで開いた場合や、旧版で復元した場合の動作は保証しない。ダウングレード非対応として README に記載する。
- CSV の「読値」「前回値」列は数値列として扱われており、先頭が `-` でも数式対策の `'` を付けない。この扱いは変更しない。

## 3. 設計

### 3.1 core の読値検証

- `reading_values.validate_reading_value` にキーワード引数 `allow_negative: bool = False` を追加する。既定値を `False` として、引数を省略した呼出しでは従来どおり負数を拒否する (安全側に倒す)。負のゼロ (`value == 0 and value.is_signed()`) は `allow_negative` にかかわらず拒否する。
  - エラー文言は条件に応じて分ける (例: 「読値は有限の 0 以上の数値で指定してください。」「読値に負のゼロは指定できません。0 を入力してください。」)。
- 負数許容の共通判定関数 `allows_negative_reading(calculation_method, value_schema)` は `CalculationMethod`・`ValueSchema` を定義する `contract_models.py` に置き、`reading_values.py`・各 Service・`db/integrity.py` からは一方向に参照する (`contract_models.py` ↔ `reading_values.py` の循環 import を避ける)。
- `validate_initial_reading` は引き続き `delta` 専用とし、負数を拒否する。新規の負のゼロは、内部で呼ぶ `validate_reading_value` で拒否する。既存 DB の読値初期値は読み出し時の互換対応 (3.4) を経てから検証する。
- `measurement_definition_service.py` の作成・更新では、警告閾値の新規入力に負のゼロを許さない。符号なしのゼロは引き続き許容し、他の設定項目の入力条件は変更しない。
- `assignment_calculation.validate_assignment_reading` は、受け取る測定定義から `allows_negative_reading` で負数の許容を判定する。`ReadingPrecision` Protocol に `calculation_method`・`value_schema` を追加するか、許容の可否を引数で受け取る。`validate_persisted_assignment_reading` にも同じ判定を渡す引数を追加する。
  - `assignment_calculation_settings.py` の `preview_correction` で割当の `initial_reading` (`delta` 専用の読値初期値) を検証する呼出しは、`allow_negative=False` (または `validate_initial_reading`) のままとし、負数を許容しない。
- 呼出し元 (`manual_reading_validation.py`、`reading_write_orchestration.py`、`reading_preview.py`、`assignment_calculation.py` の交換境界の計算、`assignment_calculation_settings.py`、`meter_replacement_service.py`) で、測定定義の計算方法・値形式に基づく判定を渡す (`manual_reading_validation.py` では `validate_reading_value` と `resolve_meter_reading_submission` の両方に渡す)。
- `UsageDeltaCalculationService` は `raw_only` で差分を計算しないため変更しない。

### 3.2 契約 (`contract_models.py`)

- 符号付き・有限・負のゼロ拒否の読値型 (仮称 `SignedReadingAsString`) を追加する。既存の `SignedDecimalAsString` (集計式の係数等で使用) の意味は変更しない。
- `MeterReadingSubmission.raw_reading` は、転送時の形式検証として符号付きを受け付ける。計算方法は予定枠の解決後に判明するため、転送時に符号を判定しない。
- `MeasurementDefinitionData.last_reading` も `SignedReadingAsString | None` とし、`calculation_method`・`value_schema` に応じて負数許容を検証する (`raw_only` で負の読値を保存した後に `db/repositories.py` の `list_measurement_definition_data` で失敗しないようにする)。
- `ResolvedMeterReadingSubmission` に `calculation_method: CalculationMethod` を必須で追加し、`allows_negative_reading` を満たさない負の読値は解決時に拒否する。`resolve_meter_reading_submission` と `meter_reading_sync.ReadingSubmissionResolver` の型にも `calculation_method` を必須引数として追加し、渡し忘れを型検査で検出できるようにする。
- 交換の読値 (`ReplacementDefinitionReadingSubmission`、`MeterReplacementSubmission` の読値) も符号付きを受け付け、負のゼロは転送契約で拒否する。PC での交換と、同期で実際に適用する交換は、測定定義の解決後に計算方法・値形式に基づいて検証し、`delta` の負数を拒否する。
  - 交換同期では、転送形式が正しい古い再送は `delta` の負数を含んでいても、従来どおり `IGNORED_STALE` とし、DB を変更せず再計算もしない。適用対象では `meter_reading_sync.py` の `replacement_items` → `recalculate_after_replacement` の経路で符号を検証し、拒否時は既存のセーブポイントで交換・境界・後続実測等への変更をロールバックする。
- JSON スキーマ (`WithJsonSchema`) は符号付きのパターン (`SIGNED_DECIMAL_STRING_PATTERN`) を示す。構文上マッチする負のゼロの拒否は validator で担保する。
- 契約の独立性 (Service・UI・DB 実装に依存しないこと、契約モジュール間の循環 import がないこと) を維持する。

### 3.3 集計・検針履歴

- `reports.py` では `_DefinitionHistory` の生成対象が `_eligible(definition)` (`delta` かつ `decimal_string`) と集計式の項に限定されているため、`raw_only` の読値は従来どおり集計処理に入らない (集計対象外のまま)。`_validate_reading`・`_DefinitionHistory` の欠測判定・`_observe_boundary` の負数判定 (`value < 0`) は `value.is_signed()` に見直し、負のゼロが保存されている場合も業務エラー (不整合) として検出する。
- `reading_history.py` の状態不整合判定 (`HIST_STATE_MISMATCH`) では、`raw_only` かつ `decimal_string` の読値列 (`_reading` の `raw_reading`、`_boundary` の `old_final_reading`・`new_initial_reading`・`previous_measured_reading`) の負数を不整合にしない。一方、負のゼロ (`value == 0 and value.is_signed()`) は方式を問わず不整合とし、それ以外の数値列 (`delta` の全列および `raw_only` の `last_reading`・`usage_delta` 等) は `value.is_signed()` で負数・負のゼロの両方を不整合とする。
- 使用量集計・集計式・JSON 一括出力の値とコードは変更しない (`raw_only` は集計対象外のまま)。

### 3.4 DB 整合性検査 (復元時)

- スキーマ・`SCHEMA_VERSION`・移行処理は変更しない (DB の読値列に符号の CHECK 制約はない)。
- 保存済みの `measurement_definitions.warning_threshold` と `meter_assignments.initial_reading` に限り、有限の plain decimal 文字列として妥当な負のゼロを、`db/repositories.py` の該当列の読み出しと `db/integrity.py` の `_check_decimal_fields` で符号なしのゼロとして扱う (`-0.00` は `0.00` として扱い、小数桁数を保つ)。既存 DB を開いた場合も復元候補の検査も同じ扱いとし、保存済みの文字列は書き換えない。新規入力にはこの変換を適用しない。
- `_check_decimal_fields` のその他の列では、負のゼロ (`number == 0 and number.is_signed()`) を拒否する。この互換対応を実測値・交換読値・使用量等には広げない。
- `_DECIMAL_FIELDS` による一律の「0 以上」検査から、`raw_only` で負になり得る列 (`reading_transactions.raw_reading`、`replacement_boundaries` の `previous_measured_reading`・`old_final_reading`・`new_initial_reading`) の符号検査のみを外す。
  - `reading_transactions.last_reading` は `raw_only` では NULL 必須、`delta` では非負のため `_DECIMAL_FIELDS` の非負検査を残し、`_check_planned_readings` でも `last_reading` に `allow_negative=True` を渡さない。
  - `replacement_events` の旧読値列 (`old_final_reading`・`new_initial_reading`) は現行仕様で常に NULL 必須であり測定定義も一意でないため、`_DECIMAL_FIELDS` から外さない。
- 上記の符号検査を外した列は、測定定義の計算方法・値形式を参照する検査で判定する。
  - `_check_planned_readings` では、`superseded` 枠や割当解決不可の枠 (`matching` が空の場合) でも `raw_reading` の符号検査が抜けないよう、`matching` の有無にかかわらず `allows_negative_reading` に基づく符号・負のゼロ検査を実行する。
  - `_check_boundaries` の SQL に `d.value_schema` を追加取得し、`allows_negative_reading` に基づいて `previous_measured_reading`・`old_final_reading`・`new_initial_reading` を検査する。
  - `raw_only` かつ `decimal_string` の読値は負数を許容し、`delta` の読値・前回値・使用量は従来どおり 0 以上を要求する。負のゼロは計算方法にかかわらず拒否する。
- 上記以外の非負・正数検査は従来どおりとし、警告閾値・読値初期値についてもゼロ以外の負数は拒否する。

### 3.5 PC 画面

- `DecimalLineEdit` に `allow_negative: bool = False` を追加する。`True` の場合は符号付きのパターンを受け付け、負のゼロを拒否し、プレースホルダーを「例: -12.5」等にする。既定の動作は変更しない。
- `direct_reading_dialog.py` の測定値と `replacement_definition_editor.py` の旧最終読値・新初期読値で、対象の測定定義が `allows_negative_reading` を満たす場合だけ `allow_negative=True` にする。
  - `replacement_registration_page.py` で交換元メーターや交換日時を切り替えたとき、および `replacement_history_page.py` で選択行を切り替えたときに再生成される各 `ReplacementDefinitionEditor` (および `raw_only` と `delta` が混在するメーター交換) で、測定定義ごとに正しく符号許可が設定されるようにする。
- 最終的な検証は core で行い、UI の検証は入力形式の早期通知にとどめる。
- 読値の表示・CSV 出力は既存の Decimal 表示を使い、負数の表示を確認する。

### 3.6 検針シート (`mobile_reading_assets/sheet.js`・`sheet.css`)

- 既存の `DECIMAL_PATTERN` と `parseDecimal` (倍率・ロールオーバー値・力率等で使用) は変更しない。`raw_only` かつ `decimal_string` の測定値の検証にだけ符号付きの解析を使う。BigInt による固定小数点の表現・比較・書式化が負数を扱えることを確認する。
  - JavaScript では `BigInt("-0") === 0n` となり `n < 0n` では負のゼロを区別できないため、文字列側の先頭 `-` と `n === ZERO` の組合せで負のゼロ (`-0`・`-0.00` 等) を明示的に拒否する。
- `raw_only` かつ `decimal_string` の数値入力欄の隣に「±」切替ボタンを表示する。`delta` と力率の入力欄には表示しない。
  - 現行の `<label class="field-row">` 内に `<button>` を同居させると HTML 仕様違反 (1 つの `<label>` に複数の labelable 要素) となり、ラベル「今回値」のタップで「±」ボタンが誤作動する恐れがある。そのため、入力行は `div.field-row` とし、`<label for="...">` を `<input>` に紐づけて「±」ボタンを `<label>` の外に分離する。
  - 押下時は入力値を `trim()` したうえで先頭の `-` を付け外しする。空欄または空白のみの場合は `-` を入力した状態にし、入力欄へフォーカスを戻す。
  - 切替は通常の入力変更と同じ処理を通す (確認の解除、IndexedDB への自動保存、同日後続枠の前回値の再表示)。
  - `aria-label` (例: 「符号を切り替え」) を付け、`sheet.css` でスマホ縦横・PC で操作しやすいタップ領域・配置にする。
- `raw_only` の入力エラーの文言を、負数を入力できることが分かる内容にする (例: 「数値を、指数・カンマなしで入力してください。負数は先頭に - を付けます。」)。検証前に前後の空白を除去し、結果に出力する読値にも空白を含めない。
- `-`・負のゼロ・`delta` の負数などの不正・途中入力は、未確認のまま IndexedDB・途中経過 JSON に保持・復元できる。該当枠は確認できず、MR1・結果 JSON にも含めない。他の確認済み正常枠の部分出力は妨げない。不正な読値を含む実測枠が確認済み (`confirmed: true`) とされている下書きは、読込時に拒否する。
- 前回値として表示する `initial_last_reading` やシート内の先行枠の読値が負数でも、正しく表示されることを確認する (`raw_only` は参考使用量を計算しない)。
- シート・下書き・結果のデータ形式は v1 のままとし、キーを追加しない。
