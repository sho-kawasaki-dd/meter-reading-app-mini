## 1. 目的・範囲

外部の集計スクリプト等でデータを活用しやすくするため、使用量集計の数値を一括で JSON ファイルに出力する機能を追加する。日・月・暦年・年度のいずれか 1 期間を指定し、全測定定義・全集計式の期間合計を 1 ファイルに出力する。

既存の使用量集計 (5.3.6・5.3.7) と同じ計算結果を出力し、JSON 専用の業務計算は作らない。現行画面は 1 系列ずつの表示・CSV 出力であり、目的・カテゴリ・場所で絞り込む。JSON 出力はこれらの選択に依存せず、全目的・全対象を同一の読取スナップショットから出力する。

| 対象 | 対象外 |
| --- | --- |
| 日・月・暦年・年度を 1 つ指定した期間合計の JSON 出力 | 期間内の時系列 (例: 年度の月別内訳) の出力 |
| 全目的 (`operational`・`billing`・`audit`) の全測定定義・全集計式 | 目的・カテゴリ・場所による出力対象の絞り込み |
| 無効化済み定義、集計対象外の定義、期間内に適用版がない式の列挙 (値は `null` と理由) | 対象間・目的間の総合計 |
| 品質情報 (欠測系・警告・情報コード)、式版ごとの構成項目・係数・寄与 | 個々の検針・交換境界・前回基準の明細 (画面・CSV で確認する) |
| 集計 Service の全目的・全対象スナップショット取得への拡張 | 集計ルール・欠測判定・CSV / PNG 出力の変更 |
| `pyproject.toml`・`uv.lock` のアプリ版数を `0.2.2` に更新 | DB スキーマ・移行の変更 (v5 を維持) |
| 改修後の Windows 検証用インストーラーのビルド・成果物検査 | タグ付け・Release 作成・正式配布、開発 PC でのインストール・既定保存先での起動 |
| 正本 (3.2・5.3.6・6.1 章)・README の更新 | JSON の取込・外部連携の自動化 |

検証用成果物は正式な配布物ではなく、Release に添付しない。インストールを伴う実地確認は、実データのない Sandbox / VM で利用者が行う。タグ付け・Release は別途、利用者の承認と Phase 5c の手順に従う。

## 2. 決定事項

利用者確認 (2026-11-25) で確定した方針は以下のとおり。

| # | 論点 | 決定 |
| --- | --- | --- |
| D1 | 期間指定と出力する数値 | 日・月・暦年・年度を 1 つ指定し、その期間の合計を全対象分出力する |
| D2 | 目的の扱い | 全目的を一括で出力し、各対象に `purpose` を記録する。目的をまたいだ合算はしない |
| D3 | 内訳の詳細度 | 集計値と品質情報に加え、式版ごとの構成項目・係数・寄与を出力する。個々の検針・交換境界・前回基準の明細は含めない |
| D4 | 無効化済み・集計対象外 | 無効化済みを含む全定義・全式を列挙する。集計対象外の定義や期間内に適用版がない式は値を `null` とし、理由を記録する |
| D5 | 数値の表現 | 使用量・係数・寄与は無丸めの plain decimal 文字列とする。値なしは `null`、計算済み 0 は `"0"` 等の文字列とし区別する |
| D6 | 形式・保存 | UTF-8 (BOM なし) の JSON とし、既存の一時ファイル書込・置換が完了してから成功を通知する |
| D7 | 版数・検証用ビルド | アプリ版数を `0.2.2` に更新し、v0.2.1 と同じ手順で検証用インストーラーをビルド・検査する (2026-11-25 利用者指示) |

### 2.1 その他の前提 (計画として採用)

- 期間の指定方法は以下とする。内部と JSON の終了境界は半開区間とし、終了日を含まない。

  | 単位 (`unit`) | 指定値 | 期間 | 表示名の例 |
  | --- | --- | --- | --- |
  | `day` | 業務日 | `[指定日, 翌日)` | `2026-11-25` |
  | `month` | 年・月 | `[月初, 翌月初)` | `2026年11月` |
  | `calendar_year` | 年 | `[1 月 1 日, 翌年 1 月 1 日)` | `2026年` |
  | `fiscal_year` | 年度 (開始年) | `[4 月 1 日, 翌年 4 月 1 日)` | `2026年度` |

- 期間の境界は既存の `_period_boundaries` と同じ規則で算出し、画面の集計と年度の定義を共有する。
- 開始日が現在業務日より後の期間は、UI で選択できず、Service でも業務エラーとして拒否する。現在業務日を含む期間は既存規則どおり現在業務日の翌日で打ち切る。未来日を 0 や欠測として扱わない。
- JSON 出力の初期値は、ダイアログを開いた時点の現在業務日を含む期間とする。集計画面の期間・目的・カテゴリ・場所・系列は引き継がない。
- 期間は名目の期間 (`nominal_start`・`nominal_end`) と実際の集計期間 (`start`・`end`) を両方出力する。`is_in_progress` は画面の「途中値」判定 (`AggregationPeriod.is_in_progress`) と一致させる。これとは別に、集計期間が現在業務日を含むかどうかを `includes_current_business_date` として出力する。日単位の当日分は締め前の可能性があることを外部スクリプトでも判別できるようにするためである。
- 個々の数値は `AggregationReportService` と同じ計算結果とする。同じ期間・目的について、出力の各値・コードが画面用の `get_report` の結果と一致することをテストで保証する。
- 直接集計は測定定義の現在の `purpose`・カテゴリ・単位、式集計は式自身の属性で分類する。式とその構成定義は独立した結果として出力し、二重計上を避けるため総合計は出さない。
- 出力対象の選定・計算中に業務エラー (状態と値の不整合、式の参照先不明等) が発生した場合は、部分的な JSON を作らず出力全体を中止する。既存ファイルは変更せず、画面と同じ業務エラーを表示する。
- 表示桁数 (`decimal_places`) による丸め値は出力しない。`decimal_places` を属性として出力し、丸めは利用側に委ねる。

## 3. 設計

### 3.1 JSON 形式 v1

トップレベル (キー順を固定する):

| キー | 型 | 内容 |
| --- | --- | --- |
| `kind` | 文字列 | 固定値 `"mrm-usage-aggregation"` |
| `v` | 整数 | 形式の版数。本改修で `1` |
| `generated_at` | 文字列 | 出力日時。UTC 秒単位の `YYYY-MM-DD HH:MM:SS` (既存 DB / シートと同じ形式) |
| `generated_at_local` | 文字列 | 業務タイムゾーンの出力日時 (オフセット付き ISO 8601) |
| `business_timezone` | 文字列 | 業務タイムゾーンの IANA 名 (例: `"Asia/Tokyo"`) |
| `as_of_business_date` | 文字列 | 集計時の現在業務日 `YYYY-MM-DD` |
| `period` | オブジェクト | 3.1.1 |
| `results` | 配列 | 3.1.2。全測定定義・全式 |

#### 3.1.1 `period`

`unit` (`day` / `month` / `calendar_year` / `fiscal_year`)、`label` (表示名)、`nominal_start`、`nominal_end`、`start`、`end`、`is_in_progress`、`includes_current_business_date` を持つ。日付は `YYYY-MM-DD`、`*_end` は含まない終了日とする。

#### 3.1.2 `results` の各要素

共通項目:

| キー | 内容 |
| --- | --- |
| `target_type` | `"definition"` / `"formula"` |
| `target_id` | 測定定義 ID / 式 ID。外部スクリプトは `target_type` と `target_id` の組を照合キーとする |
| `display_name`・`unit`・`category`・`purpose` | 名称・単位・カテゴリ・目的。カテゴリ・目的は固定の英語コード |
| `decimal_places` | 表示桁数 (未指定は `null`) |
| `location_ids`・`locations` | 場所 ID の昇順配列と、`{location_id, location_names}` の配列。場所名は既存の場所一覧 (`list_meter_locations`) と同じ規則で取得し、名称の不一致がある場合は複数名を保持する。物理メーター一覧に該当 `location_id` がない場合は `location_names` を空配列 `[]` とする |
| `value_state` | 3.1.3 の固定コード |
| `value` | 無丸めの plain decimal 文字列または `null` |
| `missing_codes`・`warning_codes`・`information_codes` | `AggregationCode` の固定値の配列 (既存の並び順) |
| `issues` | `{code, message}` の配列。同じコード・メッセージの組を重複なく、`AggregationCode` の定義順 → `message` 昇順で日本語の説明として出力する |
| `missing_definition_ids` | 式で一部の構成定義にのみ値がある部分値 (`MISSING_PARTIAL_ITEMS`) のときに、値がない構成定義 ID の昇順配列。全項目に値がない場合や測定定義では空配列 `[]` とし、既存の `AggregationResult.missing_definition_ids` と一致させる |
| `reason` | 値が `null` の理由 (日本語)。`value` が `null` (`no_value`・`excluded`・`not_applied`) のときは非 `null`、値がある (`calculated`・`reference`) ときは `null` とする |

測定定義の追加項目: `is_active`、`calculation_method`、`value_schema`、`reading_cycle`。無効化済みの集計対象外定義 (`excluded` かつ `is_active = false`) にも、既存の `_definition_result` と同じく `INFO_DISABLED_DEFINITION` を付与する。

式の追加項目: `cycle_group`、`coverage` (`"full"` / `"partial"` / `"none"`)、`applications`。`coverage` は名目期間 (`nominal_start`〜`nominal_end`) ではなく、実集計期間 (`start`〜`end`) に対する適用範囲で判定する。期間内に有効な式版がない式 (`not_applied`) は `coverage = "none"` とし、`location_ids`・`locations`・`applications`・`issues`・各コード配列・`missing_definition_ids` をすべて空配列 `[]` とする。

`applications` は期間内に適用される式版ごとに出力する:

- `version_effective_from`、適用区間の `start`・`end` (含まない)、`is_retroactive`、版の寄与合計 `contribution` (値がなければ `null`)。
- `terms`: 版の各項目について `measurement_definition_id`、`display_name`、`location_id`、`coefficient`、適用区間内の元使用量合計 `source_usage`、寄与合計 `contribution`、`is_active` を出力する。並びは版の `sort_order` に従う。
- 項目別の合計は、既存の集計明細 (`AggregationDetail`) のうち集計採用された明細 (`detail.contribution is not None`) のみを版・測定定義ごとに `exact_add` で加算して求め、途中で丸めない (確認待ち割当 `MISSING_ASSIGNMENT_PENDING` で除外された明細の `source_usage` を混入させない)。採用明細がない項目は `source_usage`・`contribution` を `null` とする。全項目・全版の寄与の和が式の `value` と一致することをテストで保証する。

#### 3.1.3 `value_state`

| コード | 条件 | `value` | `reason` |
| --- | --- | --- | --- |
| `calculated` | 値があり、欠測系コードがない | 文字列 (`"0"` を含む) | `null` |
| `reference` | 値があり、欠測系コードがある (画面の参考値) | 文字列 | `null` |
| `no_value` | 集計対象だが値がない。欠測系コードがあれば欠測による値なし、なければ期間内に予定枠・交換がない | `null` | 欠測系コードあり: 「欠測系の理由により使用量を算出できません。」 / なし: 「この有効期間に予定枠・交換境界はありません。」 |
| `excluded` | `raw_only`・力率等、使用量集計の対象外の測定定義 | `null` | 既存の対象外理由 (`exclusion_reason`) |
| `not_applied` | 実集計期間内に有効な式版がない式 | `null` | 適用開始前: 「指定期間内に式の適用は開始されていません。」 / 無効化中: 「指定期間内に有効な式版がありません (無効化中)。」 |

`not_applied` の理由は、実集計期間の排他的な終了日 `end` より前に発効した版がなければ「適用開始前」、あれば「無効化中」とする。`effective_from_date == end` の版は発効済みに数えない。`is_initial` は初回登録版を示し、有効開始日が最も早い版を示すとは限らないため、理由の判定には使わない。

警告は値の状態と独立に `warning_codes` で示す。途中値は `period.is_in_progress` で示す。

#### 3.1.4 並び・書式

- `results` は `target_type` (定義 → 式)、`purpose` (`operational` → `billing` → `audit`)、`category` (`Category` の定義順: `electricity` → `gas` → `water` → `boiler` → `others`)、`display_name`、`target_id` の順に並べ、同じ DB・同じ条件では出力が決定的になるようにする。
- Decimal は、値が 0 (`value.is_zero()`) のときは符号を除いて (`value.copy_abs()`) から `format(value, "f")` で指数表記のない文字列にし、`"-0"`・`"-0.0"` を出力しない。既存の plain decimal 規則に適合することを検査し、業務数値に `float` を使わない。
- `json.dumps(..., ensure_ascii=False, indent=2)` 相当とし、改行は LF、末尾に改行を付ける。文字列セルの数式注入対策は CSV 固有の規則であり、JSON には適用しない (値は加工せずに出力する)。
- 既定のファイル名は `meter-usage-<unit>-<期間開始日>-<保存先ダイアログ表示日時>.json` (例: `meter-usage-fiscal_year-2026-04-01-20261125_112300.json`) とする。保存先ダイアログを開く直前に取得した時刻と業務タイムゾーンを既存の `local_timestamp_for_filename(now, business_tz)` に渡し、OS ローカル時刻に依存しない。ファイル名の日時は、保存先確定後に取得する JSON 本文の出力日時とは別とする。

### 3.2 core

- `AggregationReportService` にオプション引数 `clock: Callable[[], datetime] = utc_now` を追加し、`app_context.py` から既存の `clock` を注入する。あわせて、全目的・全対象を 1 回の読取トランザクションで取得する公開メソッド (仮称 `get_export_snapshot(spec)`) を追加する。
  - 単一読取トランザクション内で `clock()` と `timezone_provider()` を 1 回だけ評価し、`generated_at` (UTC 秒単位)・`business_timezone` (IANA 名)・`as_of_business_date` をすべて同じ時刻・タイムゾーンから導出する。`timezone_provider()` の戻り値が `ZoneInfo` でない場合は業務エラー (`InvalidTimezoneError` 等) として拒否する。
  - 期間の確定、測定定義・式・式版・割当・確認待ち・検針結果・交換境界・場所名の読取を、同じ読取トランザクション内で行う。
  - `_build_report` の対象選定と期間計算を内部関数に分け、目的フィルターなし・式未適用の列挙を含む選定でも、測定定義ごとの履歴を 1 回だけ構築する。画面用 `get_report` の引数・戻り値・挙動は変更しない。
  - 式の検証範囲は既存の `get_report` と一致させ、全式の版履歴構造 (`_validate_versions`) を検証し、参照先定義の存在・属性検証は期間内の適用版に対して実施する。
  - スナップショット契約には、`generated_at`、`business_timezone`、`as_of_business_date`、`period`、全測定定義のメタデータ (`is_active`・`calculation_method`・`value_schema`・`reading_cycle` 等を含む)、全式の結果と未適用式情報 (構成定義の `display_name`・`location_id`・`is_active` を参照可能にする)、場所一覧 (`location_id -> location_names`) を保持する。
- 場所名は `AggregationReportRepository` に既存の場所一覧読取 (`list_meter_locations`) を追加して取得する。新たな SQL を追加する場合は sqlite3 Repository 側に置き、値はプレースホルダで渡す。
- JSON の組立は PySide6 に依存しない純粋な関数・Service として新規モジュール (仮称 `core/aggregation_json.py`) に置く。入力はスナップショットとし (出力日時・タイムゾーンもスナップショットから参照する)、JSON 文字列を返す。ファイルの書込は行わない。
- 期間の指定は契約として定義する (仮称 `AggregationExportPeriodSpec`: `unit` と `anchor` 日付)。月・暦年・年度は `anchor` を期間内の任意の日として受け取り、境界は 2.1 の規則で確定する。
- 現在時刻は注入した時計と `core/timeutil.py`、業務タイムゾーンは既存の `timezone_provider` から取得する。`datetime.now()` を直接使わない。
- JSON にアプリ版数は含めない。現行アプリは実行時に版数を取得する仕組みを持たず、exe にもパッケージのメタデータを同梱していないため、本改修で配布設定を変更しない。形式の識別は `kind` と `v` で行う。

### 3.3 UI

- `DashboardWindow` (使用量集計) に「全対象を JSON 出力…」ボタンを追加し、専用のモーダルダイアログ (仮称 `AggregationJsonExportDialog`) を開く。
- ダイアログでは単位 (日 / 月 / 暦年 / 年度) と指定値を選ぶ。日は日付、月は年・月、暦年・年度は年を入力する。選択中の期間 (例: `2026-04-01 〜 2027-03-31 (2026年度)`) と、全目的・全測定定義・全集計式を出力することを表示する。進行中の期間 (月・暦年・年度) を選んだ場合は現在業務日までの途中値であることを、日単位で現在業務日 (当日) を選んだ場合は当日分が締め前の可能性があることを表示する。
- 開始日が現在業務日より後の期間は UI で選択できないようにする。保存先確定後に Service がその時点の業務日で期間を再判定し、開始日が未来なら拒否する。保存先の選択中に日付をまたいだこと自体はエラーとせず、集計終了日と途中値・当日の判定には確定後の業務日を使う。
- 「保存…」で既定ファイル名を生成し、既存の `export_file_with_dialog` を再利用して保存先を選ぶ (`.json` 拡張子補完時の上書き確認・待機カーソル・ログ記録・`run_guarded` を既存出力と統一する)。キャンセル時は集計も書込も行わない。保存先確定後にスナップショットを 1 回取得し、JSON 本文の出力日時・業務日・実集計期間はすべてそのスナップショットから決める。
- 既定ファイル名生成と `atomic_write_text` + `FileOutputError` 変換の保存関数 (仮称 `save_aggregation_json`) は `ui/aggregation_export.py` に置く。置換完了後に、保存先・実際に出力した集計期間・出力件数を成功通知として表示する。
- 業務エラーは画面に表示し、予期しない例外はログに記録して汎用エラーダイアログで通知する。ファイル出力の失敗は既存の `FileOutputError` と同様に保存先とアクセス権の確認を案内し、成功を通知しない。
- 出力はその場で取得するため、集計画面に表示中の古い表・グラフを使わない。

## 8. 注意事項

- JSON には業務情報 (名称・場所・使用量) が含まれる。検証で出力した JSON を Git・Release・配布物に含めない。
- `v = 1` の形式を外部スクリプトが利用するため、キーの削除・意味の変更は形式の版数を上げて行う。キーの追加は互換性を確認したうえで行う。
