# 検針シート 予定日表示・日付時刻分類 改修計画

- 作成日: 2026-11-24
- ステータス: 計画中
- アプリ版数: 本計画では変更しない (版数の更新はリリース時に別途判断する)。DB スキーマ版数も変更しない
- ブランチ: `feature/mobile-sheet-datetime-tabs`
- 対象: リポジトリ直下 (`src/`・`tests/`・`docs/`)
- 仕様の正本: [ローカル検針管理アプリ開発計画書](./ローカル検針管理アプリ開発計画書.md) 5.2.1・5.2.2・6 章
- 現状・実行手順: [README](../../README.md)

## 1. 背景・目的

検針スケジュールの日付オフセット (`day_offset`) により、1 業務日の検針シートには予定のローカル暦日が異なる枠が混在する。予定日時は「業務日 + `day_offset` の暦日の検針時刻」となる。現行のスマホ用 HTML には次の問題がある。

- ピルタブを検針時間 (`reading_session`) だけで分類しているため、暦日が異なる同じ時刻の枠が 1 つのタブに混在する。
- タブを時刻の文字列順に並べているため、時系列が逆転する。例: 「翌日 06:00」が「当日 22:00」より前に並ぶ。
- カードに時刻だけを表示し、日付を表示していない。前回値の引き継ぎ表示も「同日 08:00」となり、実際の暦日がわからない。

本改修では、ブラウザ上の分類を「予定日 + 検針時間」の組に変更し、各カードに予定日を表示する。**1 業務日 1 シートの出力単位、シートの抽出条件、下書き形式、結果形式 (MR1 / 結果 JSON) は変更しない。**

| 対象 | 対象外 |
| --- | --- |
| シート JSON の各枠に、業務タイムゾーンでのローカル予定日を追加 | 出力単位 (1 業務日 1 シート)・抽出条件・ファイル名 |
| ピルタブの「予定日 + 検針時間」への分類変更 (全周期共通) | PC 側のシート出力時の絞り込み条件 (検針時間のみのまま) |
| カードへの予定日・周期の表示、前回値引き継ぎ表示への日付追加 | 下書き JSON・IndexedDB・結果 JSON・MR1 の形式変更 |
| PC 側の取込プレビューへの予定日時の表示 | DB スキーマ・予定枠生成・配信オフセットの仕様 |
| 正本 (5.2.1・5.2.2・6 章) の更新 | DB 由来の初期前回値 (`measured` 等) への参照元日時の表示 |

## 2. 決定事項

利用者確認 (2026-11-24) で確定した方針は以下のとおり。

| # | 論点 | 決定 |
| --- | --- | --- |
| D1 | ピルタブの分類単位 | 周期に関係なく、すべての枠を「予定日 + 検針時間」のタブに分類する。従来の「週次・月次・隔月」タブは廃止し、周期はカードに表示する |
| D2 | 日付の表示形式 | タブ・カードとも `11/25(水) 06:00` (月/日・曜日・時刻) とする。年は表示しない。業務日との差を表す「翌日」「前日」などの補助表示は付けない |
| D3 | 「すべて」タブの構成 | 従来どおり場所別セクションだけで構成する。セクション内のカードは予定日時順に並べる |
| D4 | PC 側のシート出力時の絞り込み | 現行どおり検針時間 (と周期区分) で選択する。同じ検針時間の別日の枠もまとめて出力される |
| D5 | PC 側の取込プレビュー | 「検針時間」列を「予定日時」列に変更し、業務タイムゾーンのローカル日時を表示する |

## 3. 設計

### 3.1 シート JSON の拡張 (Python 側)

- `MobileReadingSheetService._slot_json` で、各枠に `scheduled_local_date` (`YYYY-MM-DD`) を追加する。値は `scheduled_at` を業務タイムゾーン (`timezone_provider`) で変換したローカル暦日とする。
  - DB には `day_offset` を保存していないため、`scheduled_at` から求める。ブラウザのタイムゾーンや `Date` の解釈に依存させないため、Python 側で確定値を埋め込む。
  - タブの時刻部分には、従来どおり `reading_session` を使う。サマータイムの欠落時刻でローカル時刻がずれる場合も、検針時間の分類を変えない。
- シートの `v = 1` は維持する。追加項目を読むのは同じ HTML に内包した JavaScript だけで、PC は結果ペイロードだけを解析するため、互換性に影響しない。
- 下書きの検証項目 (枠ごとの一致検査) に `scheduled_local_date` は追加しない。下書きは同じ `sheet_id` (同じ HTML) でしか復元しないため、下書き v1 の形式を変えない。

### 3.2 ピルタブ (JavaScript)

- タブのキーを `d:<scheduled_local_date>T<reading_session>` とする (例: `d:2026-11-25T06:00`)。キーの文字列昇順は時系列順と一致する。
- 先頭は「すべて」とし、以降は予定日時順に並べる。ラベルは `11/25(水) 06:00 (完了数/総数)` とする。
- 初期自動選択は、未確認の枠が残る最も早い予定日時のタブとし、すべて確認済みなら「すべて」とする。現在時刻との近さでは選ばない (従来方針を維持)。
- 曜日は `scheduled_local_date` の年月日を `Date.UTC` で組み立て、`getUTCDay()` で求める。ブラウザのタイムゾーンの影響を受けないようにする。曜日名は `日月火水木金土` の固定表とする。
- 場所の絞り込み・未入力のみ表示・場所セクションの進捗表示は、選択中タブの範囲で動作する現行の仕組みをそのまま使う。

### 3.3 カード表示・並び順

- カード見出しの時刻 (`card-session`) を `11/25(水) 06:00` 形式の予定日時に置き換える。周期 (日次・週次・月次・隔月等) のバッジを追加する。周期の文言は PC 側の既存表示名 (`ui/models/reading_overview_model.py` の `CYCLE_LABELS`) に合わせ、JavaScript 側に同じ対応表を持たせる (`core/` から `ui/` を参照しない)。
- 場所セクション内の並び順を「予定日・検針時間 → カテゴリ固定順 → `display_name` → `scheduled_at` → `planned_reading_id`」とする。日時タブ内では日時がすべて同じになるため、従来どおりカテゴリ順・名称順で並ぶ。
- 「次へ」は同じ場所セクション内で、表示中かつ未確認の次の枠へ進む現行仕様を維持する。上記の並び順に従い、「すべて」では時系列順に進む。
- 前回値の引き継ぎ表示を「同日 08:00 の入力値を引き継ぎ」から「11/24(火) 08:00 の入力値を引き継ぎ」に変更する。引き継ぎのロジック (`scheduled_at, planned_reading_id` 順の解決、確認解除の連鎖) は変更しない。
- ヘッダーを「検針シート 業務日 2026-11-24」とし、カードの予定日と区別できるようにする。

### 3.4 PC 側の取込プレビュー

- `mobile_reading_preview_model` の列見出し「検針時間」を「予定日時」に変更し、`target.scheduled_at` を業務タイムゾーンで `YYYY/MM/DD HH:MM` 形式 (既存の `reading_overview_model` と同じ形式) に変換して表示する。
- タイムゾーンは呼出し元のダイアログが `timezone_settings.get_timezone()` で取得し、行の組立関数に渡す。UI が Repository を直接使わない層構成を維持する。
- 予定枠を照合できない行は従来どおり「不明」と表示する。
