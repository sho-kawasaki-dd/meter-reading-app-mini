# ルート配置移行計画

- 作成日: 2026-10-27
- ステータス: 進行中
- 対象: `migration_package/` 内のプロジェクト一式をリポジトリ直下へ正式配置する整備作業(開発計画書 8 章のフェーズ表には載せない)
- 正本: [ローカル検針管理アプリ開発計画書](ローカル検針管理アプリ開発計画書.md)
- GitHub: `sho-kawasaki-dd/meter-reading-app-mini`

## 1. 目的

`migration_package/` 内の `src/`・`tests/`・`pyproject.toml`・`uv.lock` をリポジトリ直下へ移し、プロジェクトの基点をリポジトリのルートに統一する。Phase 1 完了後・Phase 2 着手前に実施し、Phase 2 以降のファイル(HTML 生成、Playwright テスト、UI、`packaging/*`)を最初から最終構成で追加できるようにする。

## 2. 現状と前提

- Phase 0・Phase 1 は完了済みで、`main` は Windows / Ubuntu の必須 CI が成功した状態にある。
- 機能変更は含めない。移動と、パス・文書・CI の追随更新だけを行う。
- 調査で確認した事実:
  - `__file__` 基準のパス(`tests/test_contract_boundaries.py`、`core/logging_config.py`、`tests/test_single_instance.py`)は、`src/` と `tests/` を一緒に移動すれば変更不要。
  - `pyproject.toml` の `packages`・pyright `include`・`testpaths`・`pythonpath` は基点からの相対指定であり、一緒に移動すれば変更不要。
  - ルートの `.gitignore` は `.venv/`・各種キャッシュ・`.coverage` を除外済み。
  - `migration_package` を参照する箇所は、README、`.github/copilot-instructions.md`、`.github/workflows/ci.yml`、開発計画書、移行ガイド、完了済み計画書(`docs/plan/implemented/`)にある。
- 完了済み計画書(`docs/plan/implemented/`)は凍結記録として変更しない。内部の `migration_package` 表記とリンク切れは許容する。
- 旧企画書は変更不可の参考記録。内容を変えず `docs/plan/archive/` へ `git mv` する。
- 移行ガイド(`migration_package/README.md`)は役目を終えるため、有用な内容を README・開発計画書へ統合して削除する。
- `main` へ直接 push しない。`feature/root-layout` ブランチから PR を作り、必須チェック `test (windows-latest)`・`test (ubuntu-latest)` の成功後に merge する。チェック名は変更しない。
- 移動と文書・CI の更新は 1 つの PR にまとめ、分割による一時的な不整合を避ける。コミットは日本語の Conventional Commits(`refactor:`・`docs:`・`ci:`)とする。

## 3. 要件

1. `src/`・`tests/`・`pyproject.toml`・`uv.lock` がリポジトリ直下にあり、ルートで全品質ゲートが成功する。
2. `migration_package/` ディレクトリが存在しない。
3. CI・README・開発ガイドライン・開発計画書のパス・コマンド記述が新構成と一致している。
4. 旧企画書が `docs/plan/archive/` にあり、内容が無変更である。
5. 新規スキップ・検査無効化・閾値引き下げを行わない。
