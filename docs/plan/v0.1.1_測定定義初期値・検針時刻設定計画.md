## 1. 目的・範囲

測定定義を新規作成するときに、次の 2 点を設定できるようにする。

1. **読値初期値**: 初回実測の前回値 (基準値) として使用量の計算に使う。
2. **検針スケジュール (検針時刻を含む)**: 検針周期とあわせて検針時刻・曜日・日付等を指定し、予定枠をその設定に従って生成する。

本改修に合わせてアプリ版数を `0.1.1` とする。スキーマ版数は v4 から v5 とし、アプリ版数とは別に管理する。改修の最後に、v0.1.1 の動作確認用として検証用インストーラーをビルドする。

| 区分 | 対象 | 対象外 |
| --- | --- | --- |
| 検針スケジュール | 作成時の定義別スケジュール指定。既存のスケジュール編集と同じ範囲 (日次の複数時刻、週次の曜日、月次の日付・第 n 曜日、日付オフセット) | 任意の `HH:MM` 時刻。検針時刻は固定 6 枠 (`00:00`・`06:00`・`08:00`・`14:00`・`17:00`・`22:00`) から選ぶ |
| 読値初期値 | `calculation_method = 'delta'` かつ `value_schema = 'decimal_string'` の定義。作成時の指定と、初回実測前の既存定義への設定・訂正・解除 | `raw_only`・力率形式の定義。交換で作成された割当 (交換境界の `new_initial_reading` が正本) |
| 版数 | `pyproject.toml` と `uv.lock` の版数を `0.1.1` へ更新 | タグ付け・Release 作成 (Phase 5c の手順で利用者の承認後に行う) |
| 検証用インストーラー | 最小構成の Inno Setup スクリプトによる、ユーザー単位インストール・データ保持の検証用インストーラーのビルドと成果物の検査 | ライセンス本文・第三者通知・対応ソース・構成一覧、実行中の更新 / 削除ガード、Release 添付 (PR-5c-2・5c-3 が担う)。インストール・起動・アンインストールの実機確認 (利用者が Sandbox / VM で実施) |

## 2. 現状・着手前提

- `MeasurementDefinitionCreateInput` / `MeasurementDefinitionCreateRequest` は `initial_schedule_json` を持つ。[repositories.py](../../src/meter_reading_mini/db/repositories.py) の `create_measurement_definition` は、生成開始日を適用開始日として `measurement_definition_schedules` に保存する。定義・スケジュール履歴・初期割当は同じトランザクションで保存している。
- [definition_master_page.py](../../src/meter_reading_mini/ui/widgets/definition_master_page.py) は作成時に常に `initial_schedule_json=None` を渡すため、作成直後は周期別既定のスケジュールに従う。定義別の設定は作成後に「スケジュール」タブ ([schedule_panel.py](../../src/meter_reading_mini/ui/widgets/schedule_panel.py)・[schedule_editor.py](../../src/meter_reading_mini/ui/widgets/schedule_editor.py)) で保存する必要がある。
- [measurement_definition_service.py](../../src/meter_reading_mini/core/measurement_definition_service.py) の作成時検証は、スケジュールの種別しか確認しておらず、日次の件数・重複 (`validate_expected_daily_count`) を確認していない。
- 読値初期値を保存する列はない。交換で作成された割当以外では、初回実測の前回値が `none` となり、初回使用量は 0 になる ([previous_reading.py](../../src/meter_reading_mini/core/previous_reading.py))。
- 現在のスキーマは v4。[migrations.py](../../src/meter_reading_mini/db/migrations.py) は過去版のスキーマ検査を固定した SQL ファイル (`schema_v1.sql`・`schema_v3.sql`) から生成する。
- `pyproject.toml` の版数は `0.1.0`。Phase 5c の Release は未作成で、v0.1.0 は配布していない。
- Windows x64 の開発用 exe は [build_windows.py](../../scripts/build_windows.py) で毎回新しい `dist\pyinstaller\meter-reading-mini-<ID>` へビルドし、[verify_windows_exe.ps1](../../scripts/verify_windows_exe.ps1) で一時保存先を使って検証できる (PR-5c-1)。Inno Setup のスクリプトはまだなく、正式なインストーラーは PR-5c-2 で整備する予定である。Inno Setup 6.7.3 のソースは `packaging/dependency-sources/` に保管している。

## 3. 決定事項

### 3.1 検針スケジュールの作成時指定

- 作成フォームで「周期別既定に従う」または「この測定定義で指定」を選ぶ。
  - 既定に従う場合は `schedule_json = NULL` で履歴を保存する。後から周期別既定が変わったときは、その変更に従う (現行と同じ動作)。
  - 指定する場合は、生成開始日を適用開始日とする定義別スケジュールの初版として保存する。
- 作成用のスケジュール欄では、既存の `ScheduleEditor` を再利用し、適用開始日の欄と適用履歴欄を表示しない。適用開始日には生成開始日を使う。
  - 表示の切替だけでなく、作成モードでは生成開始日をスケジュール取得時の日付オフセット検証の基準として渡す。既存の `effective_date()` の過去日禁止と日付欄の最小日制約を経由せず、過去の生成開始日も扱えるようにする。作成後の通常編集では、従来どおり適用開始日の過去日禁止を維持する。
- 検針周期または生成開始日を変更したときは、変更後の生成開始日に有効な周期別既定スケジュールを編集欄に再設定する。編集済みの内容がある場合は、破棄してよいか確認する。
- Service の作成時検証に、日次件数の検証 `validate_expected_daily_count` と、月次・隔月パラメータの範囲検証 (`day_of_month` 1〜31、`nth` 1〜5、`edge` `'first'` / `'last'`) を追加する。違反した場合は `ValidationError` とする。
- 作成後のスケジュール変更は、これまでどおり「スケジュール」タブで適用履歴として保存する。過去の期間へは遡及適用しない。
- 生成開始日が過去の場合は、起動時・シート出力時の補完処理で、指定したスケジュールに従って過去分の予定枠を生成する。

### 3.2 読値初期値

- **保存先**: `meter_assignments` に `initial_reading TEXT NULL` を追加する (スキーマ v5)。値は有限の plain decimal 文字列とする。
  - 初期値はロールオーバー値などの割当条件で検証するため、割当に持たせる。
  - 値を持てるのは、その測定定義で最初の割当だけとする。交換境界の新メーター割当側に対応する割当では常に NULL とし、交換境界の `new_initial_reading` を正本とする。
  - DB の CHECK 制約で `initial_reading IS NULL OR length(initial_reading) > 0` を保証する。「最初の割当だけ」という条件は Service・Repository と業務整合性検査で保証する。
- **前回値の出所**: `PreviousReadingSource` に `definition_initial` を追加する。
  - 前回値の解決順は、(1) 交換境界、(2) 同じ割当内の前回実測、(3) 最初の割当の読値初期値、(4) なし (`none`) とする。
  - `definition_initial` は初期値の読値を持ち、参照元の予定日時と予定枠 ID は持たない (`null`)。
- **使用量計算**:
  - `CalculationContext` に初期値を追加する。`resolve_planned_calculation_context` で割当とあわせて解決し、割当条件 (小数桁数・ロールオーバー値) で検証する。
  - `UsageDeltaCalculationService.calculate` / `calculate_measured_reading` に、独立した基準値を受け取るキーワード専用引数 `definition_initial_reading: Decimal | None = None` を追加する。前回値の解決順に従い、交換境界も前回実測もない場合だけ初期値を使う。交換境界の新初期値が未指定の場合は定義の初期値へフォールバックせず、初回使用量 0 を維持する。初期値 0 は未指定と区別し、初期値を実測レコードや交換境界へ偽装しない。
  - PC 直接入力、スマホ取込、プレビュー、後続実測の連鎖再計算は、同じ文脈を使う。
  - `reading_write_orchestration.py` の `_get_calculation_context` は、前回実測と交換境界の 2 要素へ分解せず `CalculationContext` を返す。計算 API の全呼出箇所を更新し、直接入力・スマホ取込・各プレビュー・条件訂正・交換境界計算・連鎖再計算で、解決済みの初期値を計算エンジンまで引き渡す。
  - 初回実測の使用量は `(初回実測 − 初期値) × 倍率` とする。今回値が初期値より小さい場合は、ロールオーバー値が設定されていれば補正する。設定されていなければ負の差分として拒否する。
  - 最初の割当で初回実測前にメーター交換が発生した場合は、交換プレビュー・登録・訂正・再計算 (`calculate_boundary_usage` / `meter_replacement_service.py`) でも `old_assignment.initial_reading` を基準として `old_meter_usage_delta` を計算する。`replacement_boundaries.previous_measured_reading` と `previous_measured_planned_reading_id` は実測参照用として NULL のままとする。
  - 初期値が未設定の場合は、現行どおり初回使用量を 0 とする。
- **入力検証**:
  - 有限で 0 以上の数値であること。
  - `decimal_places` が指定されていれば、その桁数で表せること。
  - ロールオーバー値が設定されていれば、その値未満であること。
  - 対象外の値形式・計算方式の定義で指定した場合は拒否する。
  - `initial_meter_id` が未指定 (`None`) のまま `initial_reading` が指定された場合は `ValidationError` で拒否する。
- **作成後の設定・訂正・解除**:
  - `MeasurementDefinitionService.set_initial_reading(measurement_definition_id, value | None)` を新設する。
  - 有効な定義 (`is_active = True`) で最初の割当が存在し、その割当に `measured` の結果がなく、交換も発生しておらず、割当が確認待ち (`needs_review`) でもない場合だけ許可する。対象外の値形式・計算方式を含め条件を満たさない場合は `DomainError` の派生例外で拒否する。
  - 実測がまだないため、後続の再計算は不要とする。操作は 1 トランザクションで行う。
  - 画面からの既存定義更新では、「1 業務操作＝1 トランザクション」を維持するため、属性更新と初期値更新を別々に連続実行せず、編集フォームの「測定定義を保存」と同一トランザクションに統合するか、独立した初期値保存操作として分離する。
- **関連する処理への反映**:
  - 割当の計算条件を訂正するとき (ロールオーバー値の変更) は、`preview_correction` で実測値が 0 件であっても `proposed.initial_reading` を新しい条件で再検証する。適合しない場合は `preview.issues` に追加して `can_apply = False` とし、`correct_assignment` で訂正全体を拒否する。
  - 集計 ([reports.py](../../src/meter_reading_mini/core/reports.py)) では初期値を基準として扱う。`AggregationBaselineSource` に `DEFINITION_INITIAL` を追加し、`AggregationBaseline` には `source_id = definition.measurement_definition_id`、`at = assignment.effective_from`、`reading = assignment.initial_reading` を設定する。`business_date` は最初の割当の `effective_from` を業務タイムゾーンへ変換したローカル暦日とし、再有効化で変更される `definition.generation_start_date` は使わない。後付けの初期割当でも割当開始日を基準とし、無効化・再有効化によって過去の基準日や集計期間判定を変えない。これにより初期値を基準とする初回使用量を `MISSING_NO_BASELINE` の参考値にせず、初回枠が欠測した後に 2 枠目以降で初回実測された場合は `MISSING_GAP_BETWEEN_BASELINE` として扱う。初回実測前の交換境界集計 (`_observe_boundary`) でも `DEFINITION_INITIAL` を基準として整合性を検証する。
  - 小数桁数を減らす変更では、既存の初期値を表せなくなる場合を、ロールオーバー値と同じく拒否する。
- **スマホシート**:
  - シート・下書き・結果の形式 (v1) は変更せず、`previous_source` の値として `definition_initial` を追加する。
  - [sheet.js](../../src/meter_reading_mini/core/mobile_reading_assets/sheet.js) では、前回値の表示文言と参考使用量の計算 (BigInt 固定小数点演算) に対応する。
  - 出力済みのシートには、後から設定した初期値は反映されない。この場合も、取込時には PC 側で最新の DB から再計算するため、DB の結果は正しくなる。この点は仕様として正本に明記する。
- **画面**:
  - 作成フォームに「読値初期値」の入力欄 (`DecimalLineEdit`) を追加する。対象外の値形式・計算方式を選んでいる間は無効にする。
  - 既存の定義では、初回実測前かつ交換前等に限り初期値を編集できる。編集できない状態では値を表示するだけとし、編集できない理由を示す。
  - [reading_overview_model.py](../../src/meter_reading_mini/ui/models/reading_overview_model.py) の `PREVIOUS_SOURCE_LABELS` に「測定定義の初期値」を追加して直接入力画面 ([direct_reading_dialog.py](../../src/meter_reading_mini/ui/dialogs/direct_reading_dialog.py)) とスマホ取込プレビュー ([mobile_reading_preview_model.py](../../src/meter_reading_mini/ui/models/mobile_reading_preview_model.py)) に反映し、[aggregation_display.py](../../src/meter_reading_mini/ui/aggregation_display.py) の `BASELINE_LABELS` にも「測定定義の初期値」を追加する。

### 3.3 スキーマ v5・移行・復元

- `db/schema.sql` に `meter_assignments.initial_reading` を追加する。v4 時点のスキーマを `schema_v4.sql` として固定し、v4 の版別検査に使う。`packaging/meter_reading_mini.spec` と [build_windows.py](../../scripts/build_windows.py) の同梱・検証資産 (`APP_RESOURCES`) および関連テストに `schema_v4.sql` を追加し、[verify_windows_exe.ps1](../../scripts/verify_windows_exe.ps1) の期待スキーマ版を `5` に更新する。
- `db/migrations.py` に v4 から v5 への移行を追加する。`inspect_schema` の `normalize_sql` による DDL トークン一致検査を満たすため、`ALTER TABLE ... ADD COLUMN` ではなく `rebuilds_tables=True` で `meter_assignments` テーブルを一時テーブル経由で再構築する (既存行の `initial_reading` は NULL とし、`PRAGMA foreign_key_check` で参照整合性を確認する)。`SCHEMA_VERSION = 5` とし、移行・`PRAGMA user_version` の更新・版別スキーマ検査を同一トランザクションで行う。
- `db/integrity.py` の業務整合性検査と復元時の検査に、次の項目を追加する。
  - 初期値が有限で 0 以上の plain decimal 文字列であること。
  - 初期値を持つ割当が、その測定定義の最初の割当であること (交換境界の `new_meter_id`・`new_assignment_effective_from` に対応する割当では `initial_reading` が NULL であること。旧割当として交換境界を持つことは許可する)。
  - `raw_only` または力率形式 (`power_factor_percent_phase`) の測定定義の割当に `initial_reading` が保存されていないこと。
  - 初期値がロールオーバー値未満であること (`needs_review` の割当を除く)。
- 移行で既存の使用量を変更しない。

### 3.4 検証用インストーラー

- 目的は v0.1.1 の動作確認に限る。配布物ではなく、Release に添付しない。出力ファイル名・`AppVerName`・ウェルカム画面表示等で「検証用」であることを明示する (例: `meter-reading-mini-0.1.1-verification-setup.exe`)。なお、`AppId` を正式版と共通にするため、上書き更新時に旧名のショートカットが残らないよう、`AppName` やスタートメニューのアイコン名自体には「検証用」を含めない。
- `packaging/` に最小構成の Inno Setup スクリプトを追加する。PR-5c-2 ではこのスクリプトを拡張して正式なインストーラーにし、検証用と正式版で別のスクリプトを並存させない。
  - Inno Setup 6.7.3 を使い、管理者権限を必要としないユーザー単位のインストールとする (`PrivilegesRequired=lowest`)。対象は Windows 10 以上の x64 とする。
  - アプリ版数は `pyproject.toml` から取得し、スクリプトに直接書かない。`AppId` は固定値とし、正式版でも同じ値を引き継ぐ。
  - インストール先とデータ保存先 (DB・バックアップ・ログ) を分離し、アンインストールで保存先を削除しない。
- ビルドは既存の [build_windows.py](../../scripts/build_windows.py) と同じ方針とする。
  - PyInstaller の出力は毎回新しい出力先に作成し、成功した今回のビルドだけをインストーラーの入力にする。`.build-in-progress` が残った出力や過去の出力は使わない。
  - インストーラーも毎回新しい出力先に作成し、成功時にだけ確定する。
  - インストーラー作成の手順を `scripts/` に追加する (例: `build_windows.py` にインストーラー作成の工程を追加、または `scripts/build_windows_installer.py` を新設)。Inno Setup のコンパイラ (`ISCC.exe`) の場所は引数または環境変数で指定し、版が 6.7.3 でなければ失敗させる。
- 成果物の検査:
  - 版数が `0.1.1` であること。
  - インストーラーに業務データ (DB・バックアップ・ログ・生成済み検針 HTML / JSON) が含まれないこと。
  - SHA256 を出力し、ビルド記録に残すこと。
- 成果物 (`dist/` 配下) は Git に含めない。
- 開発 PC ではインストーラーを実行しない。既定の保存先を使うインストール・初回起動は行わない。インストール・起動・アンインストールの確認は、利用者が実データのない Sandbox / VM で行う。

### 6.1 読値初期値

- [ ] 初期値ありの初回使用量が `(初回実測 − 初期値) × 倍率` となること。Decimal の精度を維持し、丸めないこと。
- [ ] 計算 API の単体テストで初期値 0 と未指定を区別し、直接入力・スマホ取込・各プレビュー・条件訂正・連鎖再計算の経路でも、初期値が計算エンジンまで届いて `last_reading`・`usage_delta` に反映されること。
- [x] 今回値が初期値より小さい場合に、ロールオーバー値があれば補正し、なければ拒否すること。
- [ ] 初期値なしの場合は、現行どおり初回使用量が 0 になること。
- [ ] 交換後の新メーターでは交換境界の値が優先され、定義の初期値を使わないこと。交換境界の新初期値が未指定の場合も、定義の初期値へフォールバックせず初回使用量 0 となること。
