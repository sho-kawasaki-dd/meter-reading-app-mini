## 1. 目的

PC の UI で次の一連の操作を完結させる。

1. 対象業務日・検針時間・周期区分を選択し、自己完結型 HTML 検針シートを出力する。
2. スマホから戻った MR1 結果テキストを貼り付けるか、結果 JSON ファイルを読み込む。
3. 保存前に各枠の現在状態、前回値、使用量、警告、入力の採否を確認する。
4. 有効な担当者を指定し、採用する結果を一括確定する。

差分プレビューは DB を変更せずに実施し、確定時に最新状態で再検証する。Android 実機での利用確認も本フェーズの完了条件とする。

### 2.2 不足

- シート生成・結果取込 Service が `AppContext` に組み込まれていない。
- PC 直接入力用プレビューは仮想入力 1 件を前提とし、同じ測定定義の複数結果を順に反映する一括プレビューに対応していない。

- `MeterReadingSyncService.sync` がトランザクションを自ら開始するため、確定時の再プレビューから保存までを同じトランザクションにまとめられない。
- `MobileReadingDialog`、一覧表示用モデル、MainWindow への導線がない。
- 同期応答の `detail` は英語であり、UI 向けの日本語結果概要がない。

## 4. 設計方針

### 4.1 core・Repository

- `core/mobile_reading_import.py` に一括プレビューと確定を統括する Service を置く。
- シート出力には既存の `MobileReadingSheetService` を再利用する。
- `AppContext` にはシート出力 Service と一括取込 Service を追加し、UI へ Service のみを渡す。UI から DB・Repository を直接参照しない。
- Repository Protocol と SQLite 実装は、結果プレビューに必要な予定枠・関連マスタ・既存結果を読み取る。論理削除済みのマスタも、結果の説明に必要な場合は取得対象とする。
- 重複判定は共通の純関数に集約する。UTC 秒単位の時刻、Decimal 値、構造化入力、備考の現行比較規則と、重複・古い入力・同時刻上書きの優先順を変えない。
- 検証・計算・判定の順序は core 内で共有し、Repository から Service・UI への依存を作らない。Repository が参照する共通関数も実装層から独立させる。
- 比較関数は DB から参照できる独立した契約モジュールに置く。日時は呼出し側で UTC 秒単位に正規化して渡し、契約モジュールから `timeutil`・Service・UI・DB 実装へ依存しない。新規モジュールを追加する場合は `tests/test_contract_boundaries.py` の `CONTRACT_FILES`・`CONTRACT_MODULES` と DB からの参照許可を更新する。
- 複数結果を仮想履歴へ適用できるようにする。前回値だけでなく後続実測の列挙と交換境界にも仮想状態を反映する。既存の `ReadingPreviewService` の単件動作を維持し、必要な共通ロジックを再利用する。
- 新メーター初回の交換境界は、同じ測定定義・メーターについて境界以降かつ対象枠より前にある実測の有無を、DB と仮想状態を統合した履歴で判定する。境界候補は DB 上の実測有無で絞り込まず取得し、仮想実測の追加・非実測化と `scheduled_at, planned_reading_id` の順序を反映する。
- 一括プレビューの再計算対象・順序・最初の拒否理由は現行の保存処理に合わせる。保存処理は対象の測定定義・旧メーターに対応する交換境界と新メーター以降を再計算してから、同じメーターの後続実測を再計算する。旧メーターの交換境界には対象枠より前のものも含まれ、既存の単件プレビューとは探索順が異なるため、一括処理へ無条件に流用しない。公開 `sync()` と PC 直接入力の既存動作を維持する。
- `MeterReadingSyncService` は、公開 `sync()` がトランザクションを所有する形を維持しながら、トランザクションを開始しない内部処理を持てるようにする。公開操作のネストしたトランザクションは作らない。
- 内部処理は元 payload の行番号・予定枠 ID・保存前の枠状態・実際の保存区分を件別に返し、不採用理由も型付きで扱う。公開 `sync()` の要求・応答契約、交換イベント処理、既存の結果区分は変更しない。

### 4.2 プレビュー・確定

- **入力全体の検証**: MR1 / JSON の形式、MR1 の CRC、必須項目・基本的な値の形式・同一 payload 内の予定枠 ID 重複は既存パーサどおり全体エラーとし、部分確定しない。直接 Service に渡された `MobileReadingResult` も予定枠 ID の一意性を検証する。解析失敗時は旧プレビューを破棄する。
- **行別の判定順序**: 同期処理と同じ payload 順で行を評価し、予定日時・予定枠 ID 順は前回値と後続値の解決に使う。各行は次の順で判定する。
  1. 予定枠・測定定義・割当・入力を検証し、時刻と入力内容を既存規則で正規化する。
  2. 対象行自身の前回値・使用量を計算する。負の差分等はこの段階で拒否する。
  3. 保存済み結果と同一なら重複、そうでなければ `client_updated_at` が古い場合は古い入力とする。同時刻でも内容が異なる場合は既存どおり上書きする。
  4. 採用可能な入力だけを仮想保存し、交換境界・後続実測を同期処理と同じ順序で再計算する。
- **仮想状態の原子性**: 行ごとに仮想変更を一時的に適用し、後続値または交換境界の業務エラーで拒否した場合は、その行が生じさせた仮想変更をすべて破棄する。予期しない例外は拒否として握りつぶさず送出する。
- DB にある実測と仮想的に追加・更新・非実測化された結果を統合して前後の履歴を列挙する。後から評価する先行枠が先に採用された後続枠を再計算する場合も含め、全行評価後の最終的な前回値・使用量・警告を返す。
- 拒否・重複・古い行の**入力内容**は適用しない。ただし、別の採用行に伴う後続再計算で、その行に対応する既存結果の `last_reading` / `usage_delta` が変わる場合は、最終プレビューと確定結果に反映する。間接再計算では既存の読値・状態・署名・担当者・到着順を変更しない。
- 行別データは「変更前の既存結果」「スマホからの入力と採否・理由」「全行評価後の最終見込結果」を分けて保持する。除外行では不採用の入力値と、保持される既存結果の間接再計算後の値を区別し、計算できない項目は未算出と明示する。
- **後続再計算件数**は、採用行の処理で間接再計算の対象となった既存実測のうち、payload の採用行を除いた予定枠 ID の件数とする。除外行に対応する既存実測は含め、同じ枠を複数回再計算した場合や値が変わらない場合も 1 件とする。拒否された行の仮想変更を破棄した試行は数えない。交換境界は `replacement_event_id`・`measurement_definition_id` の組で重複なく別に数える。
- 各行を「新規」「自動クローズからの復活」「既存結果の上書き」「重複」「古い入力」「拒否」に分類する。既存結果がある場合は結果元も表示する。
- パース後の行別拒否には、枠不在・`superseded`・確認待ち割当・測定定義に基づく入力検証・負の差分・後続値または交換境界の再計算失敗を含める。警告・拒否・無視の理由は型付きの区分と必要な表示用情報で返し、英語の例外文字列を分類に使わない。
- 警告は閾値超過、ロールオーバー、業務日・条件の不一致等を区別して返す。警告のみの行を自動除外しない。
- ヘッダー警告は、省略されていない `business_date` と、`filter` の指定済み `reading_sessions`・`cycle_groups` を、それぞれ DB 上の予定枠の業務日・検針時間・周期区分と照合する。省略または条件なしの項目は不一致としない。`generated_at` は既存パーサで形式を検証するが、シートの発行記録は DB にないため、発行日時の一致や送信者の認証には使わない。

#### 確定時の一致とロールバック

- 正常プレビュー時の入力は、`sheet_id`・ヘッダー・元の行順・状態・読値・構造化値・備考・記録日時・クライアント更新日時を含め、内部の可変な値も独立させた不変スナップショットとして保持する。UI は入力テキスト自体も保持し、正常プレビューした入力以外を確定しない。
- `expected_preview` は入力に加え、対象枠・既存結果の変更前状態、割当条件、前後の実測と交換境界など、取込・後続再計算に必要な DB 状態と行集合、および全行評価後の最終見込値を比較可能な形で保持する。無関係な DB 変更は比較対象に含めない。後続再計算は `arrival_sequence` を更新しないため、これだけを変更検出に使わない。
- 確定時は有効担当者の検証、プレビュー再計算、スナップショットの比較、採用行の保存、件別応答と最終状態の照合を単一トランザクションで行う。除外行は保存要求から除き、絞り込み後の行番号を元 payload の行番号・予定枠 ID へ対応付ける。
- 保存結果の新規・復活・上書き区分に加え、対象行と連鎖再計算された後続実測・交換境界の最終値を見込値と照合する。シート ID・確定担当者名・結果元・署名の既存監査契約も検証する。不一致は専用の業務エラーとし、全体をロールバックして再プレビューを求める。

| 場面 | 動作 |
| --- | --- |
| プレビュー中の行別業務エラー | 当該行の仮想変更を破棄して拒否し、他の採用可能行を残す |
| 公開 `sync()` の件別業務エラー | 当該行の SAVEPOINT のみ戻し、他の行は既存どおり処理する |
| 確定時の再プレビューと期待状態の不一致 | 保存を中止して全体をロールバックし、再プレビューを要求する |
| 採用予定行が保存時に拒否・無視される、または応答・最終値が不一致 | 外側の取込トランザクション全体をロールバックする |
| 予期しない例外・COMMIT 失敗 | 全体をロールバックして例外を再送出する |

### 4.3 UI

`ui/dialogs/mobile_reading_dialog.py` を作り、モーダルのタブ画面とする。

- **シート出力**: 業務日、検針時間・周期区分の複数選択、HTML 保存。業務日は現在日を初期値とし、未来日を選べない。
- **結果取込・確定**: クリップボード貼付、テキスト編集、JSON ファイル読込、プレビュー、表、区分別集計、担当者選択、一括確定。
- 一括確定は正常なプレビュー・採用対象 1 件以上・有効な担当者のすべてを満たすときだけ有効にする。
- 採用対象外の行がある場合、確定前に理由別の件数を示して明示確認を取る。
- プレビュー表は場所・測定項目・業務日・検針時間・現在状態・採否区分・前回値と出所・警告を表示する。既存結果と入力結果の状態・読値 / 構造化値・使用量を対比し、別の採用行による間接再計算も分かるようにする。
- 確定担当者には既存の `StaffComboBox` と `StaffSelectionMemory` を使い、他の画面と直前の選択を起動中だけ共有する。配置には `ui/dialog_placement.py` の `center_dialog` を利用し、スクロール等で高倍率表示時の操作到達性を確保する。
- ファイル / クリップボードの再読込開始、テキスト編集、解析・プレビュー・確定失敗時に、プレビュー・確定可能状態を同期的に破棄する。確認ダイアログの前後で入力テキストと選択した担当者が変わっていないことを確認し、旧プレビューの誤確定を防ぐ。
- HTML 出力 Service の呼出し後は、成功・空シート・生成後の保存失敗や保存先選択キャンセルを含め、DB が変更され得る場合に MainWindow へ予定枠再読込を通知する。失敗を成功として扱わず、再読込失敗も通知する。

## 5. 実装タスク

既存の PR-4a・PR-4b・PR-4c を維持する。各小見出しは PR 内の作業単位であり、新たな PR やブランチを意味しない。

- PR-4a は入力・比較と読取契約を先に整え、仮想履歴・プレビューへ進む。同期処理の整理は並行可能だが、確定処理はプレビューと同期処理の準備後に実装する。
- PR-4b は PR-4a の Service を利用し、出力・取込・MainWindow の順に接続する。PR-4c は両 PR の実装を用いて手動・実機確認を行う。
- 実装タスクは、局所テスト等で対象の挙動を検証してから `[x]` にする。統合・回帰テストと品質ゲートは別途 PR 完了前に実施し、実施結果を確認してからチェックする。資産の存在だけで完了扱いにしない。

### 5.1 PR-4a `feature/phase4-mobile-import-core`: 一括プレビュー・確定 Service

#### 5.1.1 入力検証・重複判定

- [x] パーサと Service 入口で、入力全体の形式と予定枠 ID の一意性を検証する。
  - [x] 既存パーサの MR1 / JSON 形式、MR1 の CRC、必須項目・基本形式・同一 payload 内の重複 ID の全体拒否を維持する。
  - [x] `MobileReadingResult` の直接構築時と既存の同期要求への変換時に一意性を検証する。公開 `sync()` の既存入力契約は変更しない。
  - [x] 5.1.4 で未実装の `MobileReadingImportService.preview()` 入口にも一意性検証を接続する。構築後に内部の入力が変更され得るため、使用直前に `validate_unique_entries()` を呼ぶ。
- [x] 正規化済みの結果入力と既存結果を比較する、独立した純関数を定義する。
  - UTC 秒単位に正規化した `client_updated_at`・`recorded_at`、結果状態、読値、構造化入力、備考の同一性を判定する純関数を作る。
  - 比較関数は正規化済み日時を受け取る独立契約に置き、新規契約を追加する場合は依存境界テストの対象と DB の許可リストも更新する。Decimal 値・構造化 JSON・備考の現行比較規則を変えない。
