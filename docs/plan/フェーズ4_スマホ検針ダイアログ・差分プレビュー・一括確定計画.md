## 1. 目的

PC の UI で次の一連の操作を完結させる。

1. 対象業務日・検針時間・周期区分を選択し、自己完結型 HTML 検針シートを出力する。
2. スマホから戻った MR1 結果テキストを貼り付けるか、結果 JSON ファイルを読み込む。
3. 保存前に各枠の現在状態、前回値、使用量、警告、入力の採否を確認する。
4. 有効な担当者を指定し、採用する結果を一括確定する。

差分プレビューは DB を変更せずに実施し、確定時に最新状態で再検証する。Android 実機での利用確認も本フェーズの完了条件とする。

## 2. 現状と不足

### 2.1 既存資産

| 機能 | 実装 |
| --- | --- |
| シート生成、予定枠補完・自動クローズ、枠と初期前回値の取得 | `MobileReadingSheetService` (`core/mobile_reading_sheet.py`) |
| MR1 / 結果 JSON の解析、途中経過 JSON の結果取込拒否 | `parse_mobile_reading_result` (`core/mobile_reading.py`) |
| 担当者付き検針結果の一括保存、結果ごとの SAVEPOINT | `MeterReadingSyncService.sync` (`core/meter_reading_sync.py`) |
| PC 直接入力の使用量・後続値プレビュー | `ReadingPreviewService` (`core/reading_preview.py`) |
| 確定時にプレビューを再計算して比較する既存パターン | `ReadingWriteOrchestrationService.save_manual_reading` |
| Service・Repository の組立て | `create_app_context` (`app_context.py`) |
| MainWindow の操作・ダイアログ起動 | `ui/main_window.py` |

### 2.2 不足

- シート生成・結果取込 Service が `AppContext` に組み込まれていない。
- PC 直接入力用プレビューは仮想入力 1 件を前提とし、同じ測定定義の複数結果を順に反映する一括プレビューに対応していない。
- DB Repository 内の重複・古い入力判定を、プレビューと共有できる形で呼び出せない。
- `MeterReadingSyncService.sync` がトランザクションを自ら開始するため、確定時の再プレビューから保存までを同じトランザクションにまとめられない。
- `MobileReadingDialog`、一覧表示用モデル、MainWindow への導線がない。
- 同期応答の `detail` は英語であり、UI 向けの日本語結果概要がない。

## 3. 決定事項

| # | 論点 | 決定 |
| --- | --- | --- |
| D1 | 一括プレビュー | DB を変更しない純計算とする。複数の仮想入力を予定日時・予定枠 ID 順の履歴解決へ反映し、確定時に同一トランザクション内で再計算する |
| D2 | 不採用行を含む結果 | エラー・重複・古い入力行は理由別の件数を示し、除外したうえで他の採用行を確定できる。採用対象が 0 件の場合は確定不可 |
| D3 | シート出力担当者 | 出力時に担当者を選択しない。確定担当者だけを必須とする。正本 6.1 の出力担当者選択を Phase 4 完了時に削除する |
| D4 | シート業務日の初期値 | 現在の業務日。未来日は選択不可 |
| D5 | Android 実機確認 | Phase 4 完了条件に含め、PR-4c で端末・OS・Chrome・起動経路・復元可否を記録する |
| D6 | PR 分割 | PR-4a core / PR-4b UI / PR-4c 完了記録 |
| P1 | 重複判定 | 正規化後の入力内容と既存結果の一致判定を共通の純関数にし、プレビューと Repository の双方で再利用する |
| P2 | プレビューの契機 | テキストの手編集後は「プレビュー」操作で実行する。クリップボード貼付・JSON 読込後は自動で実行する。編集・再読込開始・解析失敗・プレビュー失敗では旧プレビューと確定用データを破棄する |
| P3 | 確定時の一致 | 確定トランザクション内でプレビューを再実行し、期待プレビューと一致しない場合は全体をロールバックして再プレビューを求める。保存結果の件別区分も一致することを検証する |
| P4 | ヘッダーと DB の相違 | 業務日・出力条件と DB 上の予定枠が異なる場合は警告を表示する。枠の同定は `planned_reading_id` と DB の最新状態を正とし、ヘッダー不一致だけでは拒否しない |
| P5 | ファイル操作 | HTML は保存先と同じフォルダーの一時ファイルへ書き、完了後に置換する。JSON は UTF-8 (BOM 付き可) で読む。直近の保存フォルダーはアプリ起動中だけ記憶する |
| P6 | 確定後 | 確定・重複・古い入力・拒否の件数と拒否理由を日本語で表示し、プレビューを破棄して MainWindow の再読込を行う |

## 4. 設計方針

### 4.1 core・Repository

- `core/mobile_reading_import.py` に一括プレビューと確定を統括する Service を置く。
- シート出力には既存の `MobileReadingSheetService` を再利用する。
- `AppContext` にはシート出力 Service と一括取込 Service を追加し、UI へ Service のみを渡す。UI から DB・Repository を直接参照しない。
- Repository Protocol と SQLite 実装は、結果プレビューに必要な予定枠・関連マスタ・既存結果を読み取る。論理削除済みのマスタも、結果の説明に必要な場合は取得対象とする。
- 重複判定は共通の純関数に集約する。DB は現行の永続化規則を変えず、その関数を使用する。
- 複数結果を仮想履歴へ適用できるようにする。既存の `ReadingPreviewService` の単件動作を維持し、必要な共通ロジックを再利用する。
- `MeterReadingSyncService` は、公開 `sync()` がトランザクションを所有する形を維持しながら、トランザクションを開始しない内部処理を持てるようにする。公開操作のネストしたトランザクションは作らない。

### 4.2 プレビュー・確定

- プレビューは入力行を同期処理と同じ順序で評価する。採用可能な仮想結果だけを後続行の計算履歴へ反映し、拒否・重複・古い行は仮想履歴へ加えない。
- 各行を「新規」「自動クローズからの復活」「既存結果の上書き」「重複」「古い入力」「拒否」に分類する。既存結果がある場合は結果元も表示する。
- 拒否には、枠不在・`superseded`・確認待ち割当・入力検証・負の差分・後続値または交換境界の再計算失敗を含める。予期しない例外は拒否として握りつぶさず、UI の既存エラー処理へ送る。
- 同日複数枠や入力順が影響するケースについて、シートの枠順と結果 payload の順をそれぞれ検証する。プレビューは実際の確定順序と一致させる。
- 確定時は担当者検証、プレビュー再計算、採用行の保存、保存応答照合を単一トランザクションで行う。プレビュー差分または応答差分があれば専用の業務エラーを送出し、全体をロールバックする。
- 同期の既存仕様である「件別業務拒否は SAVEPOINT で分離、予期しない例外・COMMIT 失敗は全体ロールバック」を維持する。プレビューで事前に分類した除外行は保存要求から除く。
- 警告は閾値超過、ロールオーバー、業務日・条件の不一致等を区別して返す。警告のみの行を自動除外しない。

### 4.3 UI

`ui/dialogs/mobile_reading_dialog.py` を作り、モーダルのタブ画面とする。

- **シート出力**: 業務日、検針時間・周期区分の複数選択、HTML 保存。業務日は現在日を初期値とし、未来日を選べない。
- **結果取込・確定**: クリップボード貼付、テキスト編集、JSON ファイル読込、プレビュー、表、区分別集計、担当者選択、一括確定。
- 一括確定は正常なプレビュー・採用対象 1 件以上・有効な担当者のすべてを満たすときだけ有効にする。
- 採用対象外の行がある場合、確定前に理由別の件数を示して明示確認を取る。
- プレビュー表は場所・測定項目・業務日・検針時間・現在状態・採否区分・結果状態・前回値と出所・今回値・使用量・警告を表示する。
- ファイル読込開始、テキスト編集、解析・プレビュー失敗時に、プレビュー・確定可能状態を同期的に破棄する。旧プレビューの誤確定を防ぐ。
- HTML 出力後は MainWindow へ予定枠再読込を通知する。出力 Service が予定補完・自動クローズを実行するためである。

- 既存の PC 直接入力、交換、MR1/JSON パーサ、IndexedDB 動作に回帰がない。
- UI・core・Repository のテスト、Ruff、Pyright、全体 / `core/` / `db/` coverage 90% 以上、Windows / Ubuntu 必須 CI が成功する。
- Android 実機確認の条件・結果が記録され、正本と README が更新されている。

## 7. 対象外

- 集計ダッシュボード・CSV/PNG 出力、復元 UI、インストーラー（Phase 5）。
- 同期による交換イベント再送の訂正。Phase 3 から引き継いだ別 issue の対象とする。
- 送信者認証。MR1 の CRC-32 は破損検出、PC で付与する SHA-256 は監査用途であり、本人性を保証しない。
