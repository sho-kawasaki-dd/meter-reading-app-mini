## 1. 目的

BM-Phase 1 以降の作業を始める前に、次の 2 点を済ませる。

1. 文書をアプリ別 (`building_manager`・`meter_reading`・`work_log`) に再編し、以降の作業用計画書の置き場所を確定する。
2. 未決事項 Q13 (PDF の生成手段) と、気象庁「過去の気象データ検索」の取得・解析の実現性を、試作で確認する。BM-Phase 5・6 の設計に必要な事実を集める。

### 4.4 PDF 生成手段の比較 (Q13)

#### 試料

- [ ] 架空のクライアントの 1 日分の日誌 HTML を作る。見出し・表 (検針の使用量・最大値・最小値)・天気・複数日にまたがる個別対応事項・品質記号・長い日本語の文章を含める。
- [ ] Pillow で生成した写真を 10 枚含め、要件定義書 D29 のとおり長辺 800px・JPEG 品質 75 に変換して `data:` URI で埋め込み、幅約 80mm の 2 列に並べる。
- [ ] 要件定義書 6.2 節の CSP (`img-src data:` を含み、スクリプト・外部読込を禁止) を HTML に入れる。
- [ ] ページ寸法の上限 (200 インチ) を超える長さの日誌と、写真入りの 31 日分の月次試料も作る。両候補に同じ 3 種類の試料を使う。
- [ ] 日本語フォントは Noto Sans JP (SIL OFL 1.1) を試作の実行時に取得し、リポジトリには含めない。

#### 出力の必須条件 (WeasyPrint・Qt WebEngine の両方で確認する)

- [ ] 1 日分を、内容の高さに合わせた 1 ページの PDF にできる。高さを測る方法 (1 回組版して測り、ページの高さを指定して再度組版する等) を記録する。
- [ ] 200 インチを超える日誌を複数ページに分割でき、各ページの実寸が上限以内で、写真・表の行を途中で切らない。
- [ ] 全ページにクライアント名・業務日・版数・ページ番号 (例: 2 / 3) を表示でき、分割したページに「前ページからの続き」を表示できる。
- [ ] 月次 PDF で、各日を新しいページから始め、全ページに上記のヘッダーを表示できる。
- [ ] 日本語の組版 (禁則処理・行の折返し・表の中の改行) と、フォントの埋め込み (サブセット化) を確認する。
- [ ] 試料 HTML の CSP を緩めず、HTML の読込みから PDF 生成まで外部通信が発生しないことを確認する。
- [ ] PDF に JavaScript・添付ファイル・外部リンクがなく、メタデータ (Producer・Creator・作成者・ファイルパス等) を最小限にできる。確認には `pypdf` 等を一時的に使う。
- [ ] 出力した HTML と PDF で記載内容が一致する。

#### 実行環境ごとの確認

- [ ] WeasyPrint: 開発 PC (Windows) に MSYS2 で Pango を入れて動作を確認し、手順を記録する。Linux (WSL または CI 相当の Ubuntu) でも同じ試料で動作を確認する。

- [ ] Qt WebEngine: `QWebEnginePage.printToPdf` (非同期) で、カスタムのページ寸法を指定して出力できることを確認する。内容の高さを測る方法が、出力する HTML の CSP (スクリプト禁止) と両立するかを確認する。
- [ ] Qt WebEngine: `setHtml()` のエンコード後約 2 MB の制限を踏まえ、写真入りの大きな月次 HTML を一時ファイルから読み込み、外部通信なしで PDF を生成できることを確認する。
- [ ] Qt WebEngine: Windows で、`QT_QPA_PLATFORM` を指定しない場合に動作することを確認する。Linux のヘッドレス環境 (offscreen) で動作するかも確認する。
- [ ] 出力の必須条件を満たした候補は、製品のビルド設定や必須 CI を変えず、GitHub Actions の Windows ランナーで最小の PyInstaller 試作 exe をビルドする。使用する依存やフォントを事前導入していない Windows Sandbox / VM でその exe を起動し、サンプル PDF を生成できることを採用の必須条件とする。

## 6. リスク・留意点

- Windows での WeasyPrint は Pango の DLL に依存するため、環境構築の手順が増える。手順と所要時間も評価に含める。
- Qt WebEngine は PySide6 に含まれるが、配布物が大きくなる。Linux のヘッドレス環境では GPU・サンドボックス関係の設定が必要になる場合がある。
- 気象庁のページ構成は予告なく変わることがある。試作で得た構造は取得日時点の事実として記録し、BM-Phase 5 では構成の変化を検出して値を保存しない設計にする。
- 試料ページは 4 URL に各 1 回だけアクセスし、短時間に連続して取得しない。
