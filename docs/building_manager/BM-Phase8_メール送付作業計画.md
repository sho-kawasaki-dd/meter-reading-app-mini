# BM-Phase 8 メール送付 作業計画

- 作成日: 2026-11-28
- 状態: 設計確定・実装未着手
- 正本: [業務日誌アプリ要件定義](業務日誌アプリ要件定義.md) D32〜D38・6.4・8 章
- 前提: BM-Phase 6 (出力) の完了

## 1. 目的と範囲

クライアントごとに登録した宛先へ、担当者が Thunderbird の作成画面から日次 PDF を送れるようにする。利用者が内容と宛先を確認して送信し、送信後に結果を手動で記録できることを完了条件とする。

| 今回行うこと | 今回は行わないこと |
| --- | --- |
| クライアント別 To / Cc / Bcc 宛先と件名・本文テンプレートの管理 | 複数クライアントへの一括送付、送付時の任意アドレス追加 |
| 共通設定 DB に登録した担当者アドレスを差出人として使う | アプリからの SMTP 直接送信、アプリでの SMTP / OAuth2 認証情報管理 |
| Thunderbird の作成画面への日次 PDF 添付、送付履歴と利用者による結果確認 | 月次 PDF・HTML の添付、送信成否の自動判定 |
| 将来差し替え可能な `MailComposer` 契約 | OAuth2 の実装 |

## 2. 実施順と受入条件

### ① Thunderbird 連携の技術検証

- [ ] 実データを使わない Windows 環境で、Thunderbird の実行ファイル特定、未起動・起動中の作成画面起動、To / Cc / Bcc、`from`、件名、添付を検証する。差出人が利用可能なアカウントと一致しない場合、Thunderbird の既定アカウントに黙って切り替わらないことも確かめる。
- [ ] 本文ファイルの安全な読込方法、UTF-8 日本語、添付 URL と特殊文字を含むパス、コマンドライン長の境界を検証する。本文ファイルを安全に渡せない場合のコピー・貼付手順も確認する。
- [ ] 件名・宛先・パス等に区切り文字や制御文字を含むケースを試し、別の宛先・項目として解釈されないことを確認する。D38 の全角置換後の件名と確認画面の表示が一致することを確かめる。
- [ ] 実際の送信結果はアプリから判定できないこと、起動要求の成功が作成画面の表示・送信成功を保証しないことを確認し、利用者への表示と履歴の状態名を確定する。未検証の Thunderbird 引数仕様を前提に実装を進めない。

### ② DB 契約・業務処理

- [ ] 業務日誌 DB にクライアント別の宛先、件名・本文テンプレート、送付履歴、宛先の送付時点スナップショットを追加する。スキーマ、移行、版別検査を一緒に更新する。
- [ ] 共通設定 DB に担当者の差出人アドレスを保持し、業務日誌側は読取専用で利用する。共通 DB と業務日誌 DB をまたぐ単一業務操作の書込みは行わない。
- [ ] 送付対象の日誌・クライアント・宛先の対応、担当者と差出人、日誌版・出力履歴 ID を Service で検証する。送付時点の件名・本文・差出人・宛先を履歴に固定する。
- [ ] `MailComposer` Protocol と Thunderbird 実装を分離する。起動要求前に履歴を作成し、起動失敗を明示して再試行可能にする。アプリから直接送信する機能は作らない。

### ③ 画面・送付ライフサイクル

- [ ] 宛先・差出人・日誌の版数・生成 PDF を利用者が確認してから Thunderbird の作成画面を開く。送付時は登録済み宛先の選択・除外のみとし、クライアント違いを拒否する。
- [ ] 「送信済み」「送信しなかった」の手動確認を履歴に記録し、未確認の送付を一覧で見つけられるようにする。起動要求結果と送信結果を混同しない。
- [ ] 未確認の送付に必要な PDF・本文ファイルはデータルートの outbox に保管する。結果確認後に削除し、削除失敗は通知する。outbox はバックアップ対象外とし、復元後の残存ファイルを再送に使わない。
- [ ] 送付済みの版より新しい日誌がある場合と同一版を再送する場合に表示・確認を行う。復元後の履歴と日誌版の不整合を検出して利用者に通知する。

### ④ テスト・回帰確認

- [ ] 宛先の入力検証・論理削除・To / Cc / Bcc、テンプレート差込と D38 の置換、クライアント境界検証、担当者アドレス未設定、日誌版・出力履歴の不整合をテストする。
- [ ] Thunderbird 起動成功・起動失敗・起動ファイル不在・未確認状態からの再開・手動結果記録・一時ファイル削除失敗の状態遷移をテストする。自動テストは偽の `MailComposer` を使い、実メールを送信しない。
- [ ] 本文・宛先・添付内容をログに出さないこと、メール機能が外部通信しないこと、バックアップに outbox を含めないことを検証する。
- [ ] Windows / Ubuntu の品質ゲートと、隔離した Windows 環境での Thunderbird 手動検証を完了する。利用者が送信したことを確認できない場合も、送信成功と報告しない。

## 3. 完了確認

- [ ] BM-Phase 6 の出力契約を維持したまま、1 クライアントの日次 PDF を安全にメール作成画面へ渡せる。
- [ ] 送付操作の前に利用者が宛先・差出人・件名・本文・添付・版数を確認できる。
- [ ] 起動要求と利用者確認の結果を区別して履歴に残し、未確認のものを再送扱いにしない。
- [ ] 仕様と実装・自動テスト・隔離環境での手動検証が一致し、外部通信・業務データの誤送付・outbox のバックアップ混入がない。
